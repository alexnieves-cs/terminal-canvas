# M52 — OSC 133 and the run ledger: implementation plan

Spec: `../specs/2026-09-01-m52-osc133-design.md`. Five tasks, main first
because the renderer's marks are only ever what the shell emitted.

## Task 1 — The scanner (`verify:agent-state`)

`osc133.1/.2` RED, then `scanForBell` (renamed in spirit, not in name)
yields OSC 133 events beside the bell, across chunk boundaries, never
ringing on a mark's BEL.

## Task 2 — Injection (`verify:tmux`)

`shell-integration.1` RED, then `main/shell-integration.ts`: the rc files
written once under `userData`, `injectFor(command, env, args)` returning
the env/args to spawn with, wired into `PtyManager.create` for an absent
`command` only.

## Task 3 — The ledger (`verify:file`, `verify:pty-manager`)

`ledger.1` RED, then `main/run-ledger.ts`; `PtyManager` feeds it from the
scanner's events with the panel's cwd and a clock; `ledger:list` invoke;
`osc133.1` in `verify:pty-manager` against a real zsh.

## Task 4 — The renderer (`verify:panels`)

`osc133.1` RED, then the OSC handler in `create-terminal.ts` (markers and
decorations), the three palette rows, the Work tab's Runs section.

## Task 5 — Close

`docs/load-bearing.md` (main injects and scans; the ledger is an append
stream and records no bytes; a mark's BEL is not a bell); backlog #59 and
#46 → done; both diagrams; suite counts; build log; `npm run verify`;
merge.
