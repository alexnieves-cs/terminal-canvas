# Act I — the board that dispatches (M113–M116): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A work item record on the workspace, a `dispatch` verb that mints a worktree lane and a teammate's chat with an edge meaning *dispatched*, a return path that opens a PR through the broker and flips the card to `review`, and a Board pane plus a card kind that show it.

**Architecture:** Every piece follows a shape this repo already has. The record is M93's annotations (absent-when-empty on the workspace, parsed by the ONE parser, carried field-by-field). The control verb is M81's `status` (main asks the renderer over an ephemeral reply channel). The lane is M37's worktree manager reached from a new main invoke; the chat is the ordinary `agent:create` with an appended system prompt (M81/M101). The PR is a broker WRITE behind M102's spend card, through a client that never reads the credential store (M88). The kind is a sessionless panel like Jira's through `PanelFrame`; the pane is a `NavigatorPane` like Teammates.

**Tech Stack:** Electron 43 · TypeScript · React · esbuild-bundled `.cjs` verify suites (plain node for pure modules; the real renderer for `verify:panels`).

**Spec:** `docs/superpowers/specs/2026-09-06-m113-m116-board-design.md` — read it first; every task argues from it. Its §0 is Act 0's measurements.
