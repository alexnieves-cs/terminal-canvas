# M12: Live cwd and live command — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make "this panel's directory" a true statement — poll tmux for each pane's current path and current program, push the fact to the renderer only when it changes, and let the inspector and two consumers read it.

**Architecture:** One new field on tmux's existing global `list-panes` format; a second slow tick in `PtyManager` that emits a new `session:live` **event** only on a change; a per-panel-id renderer store mirroring `agent-state-store.ts`; the inspector renders live values *beside* the spawn-time ones, and project-prompt reading and preset capture switch to the live cwd with a spawn-cwd fallback.

**Tech Stack:** TypeScript, Electron (main/preload/renderer), tmux, React `useSyncExternalStore`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-29-m12-live-cwd-design.md`

## Global Constraints

Copied verbatim from the spec and from `CLAUDE.md`'s load-bearing details. Every task's requirements implicitly include this section.

- **`session:live` is an `IPC_EVENTS` member, never an `IPC` one.** `verify:ipc` asserts over `Object.values(IPC)` — invoke channels needing an `ipcMain.handle` — and **stays at 31**. Do not "fix" that number.
- **Nothing in this milestone may bump `registry.version()`.** That counter bumps on tier/status/focus/exit and nothing higher-frequency; a 0.5Hz fact riding it re-renders every panel on every other panel's `cd`.
- **Main sends only on an actual CHANGE.** An undeduped send is 30 messages/minute/panel for a fact that changes when a human types `cd`.
- **The `pane_dead` filtering in `parseListOutput` is untouched and load-bearing.** `remain-on-exit on` leaves a finished process listed as existing; an unfiltered poll reports a corpse's last known directory as a live fact, forever.
- **Display reports nothing without a live answer; consumers fall back to the spawn cwd.** These two rules disagree deliberately: a label makes a claim, a directory argument does not.
- **The direct backend has no live answer and none is invented.** `SessionBackend.list()` returns `null` there by contract.
- **Timers are `unref()`d.** A live interval keeps a plain-node verify suite from ever exiting.
- **tmux-dependent checks skip LOUDLY**, never silently: `ok('N SKIPPED — no tmux binary found', true, 'skipped, not passed')`.
- **Verification cadence: iterate on the RELEVANT suite, then run the full chain once before the task's commit.** There is no unit-test runner and no linter, so `npm run verify` is the whole verification story and a task is not done until it is green — but running the whole chain after every edit costs minutes per iteration for no extra signal, since each task names the one suite that can see its change. So: loop on that suite while implementing, and run `npm run verify` once at the end, immediately before `git commit`. If the chain is red for a suite this task did not touch, that is a real finding — investigate it, do not commit around it.
- **Every verify invocation in this worktree runs with `TC_VERIFY_SUFFIX` set.** A second worktree on this machine is running its own `npm run verify` concurrently, and the tmux sockets are shared by default: both suites end in `kill-server`, so an unsuffixed run here destroys that worktree's sessions mid-check and produces a red that looks like a real bug in code that is fine. Export it once per shell — `export TC_VERIFY_SUFFIX=m12` — and confirm it took: each suite prints `tmux socket: …-m12` as its first line. See `scripts/verify-socket.cjs`.
- **Do not merge, rebase, or otherwise touch `main` or any other worktree.** Another agent is working in one of them. This branch merges to `main` at the end, once, by the human.
- Commits: conventional format, scoped `m12`, e.g. `feat(m12): ...`.

Add the tick pair beside `startIdleTick`/`stopIdleTick`:

```ts
  private startLiveTick(): void {
    if (this.liveTimer) return
    this.liveTimer = setInterval(() => this.pollLive(), LIVE_TICK_MS)
    // Same reason idleTimer is unref'd: do not hold a plain-node verify process
    // open for a 0.5Hz timer nothing is waiting on.
    this.liveTimer.unref?.()
  }

  private stopLiveTick(): void {
    if (!this.liveTimer) return
    clearInterval(this.liveTimer)
    this.liveTimer = null
  }

  /**
   * One poll for every panel. backend.list() is null on the direct backend by
   * contract — not "nothing is running", but "ask the manager", and the manager
   * holds only spawn-time values — so there is no live answer there and none is
   * invented.
   */
  private pollLive(): void {
    const entries = this.getBackend().list()
    if (!entries) return
    for (const entry of entries) {
      // Only panels this manager is actually holding. An entry for a session
      // this renderer has no local session for belongs to a panel nothing is
      // subscribed to, and sending for it would grow lastLive with ids the map
      // will never clear.
      if (!this.sessions.has(entry.panelId)) continue
      const key = `${entry.cwd}\u0000${entry.currentCommand}`
      if (this.lastLive.get(entry.panelId) === key) continue
      this.lastLive.set(entry.panelId, key)
      this.send(IPC_EVENTS.SESSION_LIVE, {
        panelId: entry.panelId,
        cwd: entry.cwd,
        currentCommand: entry.currentCommand
      })
    }
  }
```

The `\u0000` separator is not decoration, and a space would be wrong: a path may contain a space, so `('/a b', 'sh')` and `('/a', 'b sh')` would collide into one key — a panel whose update is silently suppressed, for the users whose directories happen to contain the delimiter and nobody else. That is exactly the collision `railSignature` uses `JSON.stringify` to avoid, and NUL is the one byte a POSIX path cannot contain.

`entry` is typed by `SessionBackend.list()`, which returns `PtyCreateResult[] | null`. `PtyCreateResult` has no `currentCommand`, so `npm run typecheck` will fail here — follow that error to `session-backend.ts`'s tmux `list()`, which maps `parseListOutput`'s entries, and carry the new field through rather than dropping it. Widen the returned element type at whichever declaration the error names; do not cast.

- [ ] **Step 1: Write the store**

Create `src/renderer/session/live-session-store.ts`:

```ts
import { useSyncExternalStore } from 'react'
import type { PanelId } from '@shared/types'

/**
 * Where each panel IS and what it is RUNNING, as told by main.
 *
 * A third module-level store beside agent-state-store.ts, and subscribed the
 * same way: PER PANEL ID. registry.version() deliberately bumps only on
 * tier/status/focus/exit so a chatty agent cannot re-render the canvas at 60Hz;
 * a fact that changes on a 2s tick riding it would put that traffic straight
 * back, for every panel, on every OTHER panel's `cd`. This is the fourth entry
 * to record that rule — #5, #17 and #18 each found it independently.
 *
 * A CACHE of main's answer, never a second author of it. Nothing here decides a
 * cwd; main polls tmux and this holds what arrived.
 */

export interface LiveSession {
  cwd: string
  currentCommand: string
}

const live = new Map<PanelId, LiveSession>()
const listeners = new Map<PanelId, Set<() => void>>()

function notify(panelId: PanelId): void {
  const set = listeners.get(panelId)
  if (!set) return
  for (const listener of set) listener()
}

/**
 * Called by the one IPC subscription in Canvas.tsx.
 *
 * The equality check is a SECOND dedupe and is not redundant with main's.
 * Main's stops the message crossing the process boundary; this one stops a
 * re-render if a message ever arrives unchanged — a reload, a future
 * snapshot-on-load, or a second sender. The object is replaced only on a real
 * change, which is what lets the hook below hand React a stable reference.
 */
export function applyLiveSession(panelId: PanelId, cwd: string, currentCommand: string): void {
  const prev = live.get(panelId)
  if (prev && prev.cwd === cwd && prev.currentCommand === currentCommand) return
  live.set(panelId, { cwd, currentCommand })
  notify(panelId)
}

/**
 * A panel is gone for good: closed, undone, or dropped by a reset. Without this
 * the map grows for the life of the renderer and a recycled panel id inherits a
 * dead panel's directory — the same reason clearAgentState exists.
 */
export function clearLiveSession(panelId: PanelId): void {
  if (!live.has(panelId)) return
  live.delete(panelId)
  notify(panelId)
}

/** A plain read, for callers that want the answer at call time. */
export function getLiveSession(panelId: PanelId): LiveSession | undefined {
  return live.get(panelId)
}

function subscribe(panelId: PanelId, listener: () => void): () => void {
  let set = listeners.get(panelId)
  if (!set) {
    set = new Set()
    listeners.set(panelId, set)
  }
  set.add(listener)
  return () => {
    set.delete(listener)
    if (set.size === 0) listeners.delete(panelId)
  }
}

/**
 * The snapshot is the STORED object, never one built per call.
 * useSyncExternalStore compares snapshots by identity, so returning
 * { cwd, currentCommand } fresh each time makes React see a new value every
 * render and loop — the same trap attentionSnapshot exists for.
 */
export function useLiveSession(panelId: PanelId): LiveSession | undefined {
  return useSyncExternalStore(
    (listener) => subscribe(panelId, listener),
    () => live.get(panelId),
    () => live.get(panelId)
  )
}
```
