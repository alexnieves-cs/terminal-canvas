# Act II — engines, and a chat with no place (M117–M121): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two measured engines behind the M99 registry — copilot's JSONL door as the third row and its ACP door as the fourth (the first ACP client this app has been) — chat mode with a sandbox cwd and the row's model list, and the deferred seven fixed as defects; `cursor-agent` refused by name.

**Architecture:** An engine is a row in `shared/agent-backends.ts`, an adapter in `main/backend-adapters.ts`, a parser in `shared/<engine>-transcript.ts` over recorded fixtures, and NO consumer switches on the name (`verify:agent-session registry.1`). Copilot's JSONL door is codex's shape (one process per turn, served from `handleExit`); ACP is a codec over the resident-process seam with three optional encoders the manager prefers when a row has them. Chat mode is one spec flag, one row field (`sandboxArgs`), one cwd rule in main.

**Tech Stack:** Electron 43 · TypeScript · esbuild-bundled `.cjs` suites · fixtures in `scripts/fixtures/agent-session/{copilot,acp}/`.

**Spec:** `docs/superpowers/specs/2026-09-06-m117-m121-engines-design.md`.
