# M27 — Notes: implementation plan

## Context

Every panel kind this app has is a **read-out of something the machine already knows** — a
diff (`review`), a file (`file`), a config (`toolbox`), a ticket (`jira`), a process
(`terminal`). Nothing is a place the user puts thought. Today the only text-input surfaces
in the whole app are the palette's own field, a review node's commit message, and a file
panel's edit draft — all three of which are *about* something else. There is nowhere to
write "this one's the flaky-test hunt, don't kill it" beside the agent it refers to.

M22 made `FileNode` editable with a real compare-and-swap write (`main/file-write.ts`), so
the expensive half of a note panel already exists and is already hardened. What is missing
is the *creation* verb and the *prose* rendering.

**Outcome:** a `New note…` palette row that creates a real `.md` file under the selected
panel's cwd and opens it on the canvas, already in edit mode, rendered as wrapped prose
rather than numbered code lines. The note is an ordinary file — it version-controls with
the project, an agent can read it, and it survives outside the app.

Backlog: closes the note/scratch half of **#14 tier 1** and gives **#15** (the annotation
layer) a cheaper predecessor. Milestone number **M27** (next unclaimed per `README.md`;
renumber on merge if another branch lands first — the README states that rule).

---

## Decision: a note is a **file panel in prose mode**, not a sixth panel kind

`kind: 'file'` with a new `source.prose?: true`. No sixth kind.

A note is storage-identical to a file panel — same `FileSource`, same
`file:read`/`file:write`/`file:close`/`file:changed`, same CAS, same watcher. The only
genuine divergences are *rendering* and *initial state*, and both are display facts.

This deliberately avoids the whole per-kind ceremony, every item of which `CLAUDE.md`
records as a silent failure:

| Ceremony item | Why it is not needed here |
|---|---|
| `isTerminalPanel` clause (`panels.ts:184`) | already excludes `kind: 'file'` — **untouched** |
| `nextIdRef` regex `/^[nrfjt](\d+)$/`, **two** seed sites (`Canvas.tsx:374`, `:1524`) | note ids are `f<n>` — **untouched** |
| `registry.dispose` guards at 5 panel-removing sites | file panels already guarded — **untouched** |
| `clearFileResult` at 3 sites | already correct — **untouched** |
| `.file-node__editor` in `useNavGrid.ts:101` | reused verbatim — **untouched** |
| `verify:panels` 94 (source-text counts: 5 disposes / 2 `pty.kill`) | **must stay 5 and 2** |

**Do not "improve" this into `kind: 'note'` mid-implementation.** If notes later diverge
(markdown rendering, backlinks, a note index) that is the milestone that pays for the kind.

---

## What ships

1. **`file:create`** — one new IPC invoke (45 → 46 channels). Atomic create-exclusive.
2. **`New note…`** palette row in the `spawn` group, beside `Open file…`.
3. **`source.prose`** on `FileSource`, persisted, absent-stays-absent.
4. **Prose rendering** in `buildFileNodeModel` + `FileNode.tsx` — wrapped, no gutter.
5. **Auto-enter edit mode once** on a prose panel's first mount.
6. Rail tail reads `note`; inspector shows a `view: note` field.

## Explicit non-goals

- **No markdown rendering.** A renderer means a new runtime dependency (this repo refuses
  one — see `file-watch.ts`'s note) or a hand-rolled parser, whose failure mode is a
  *parser differential* against whatever the user's real markdown tool says. The value
  here is the place to write, not the formatting.
- **No note index, no backlinks, no tags, no search.**
- **No new `SettingDef`.** Nothing here is user-configurable yet.

## Files and changes

### New: `src/main/file-create.ts` (plain-node tier — imports only `node:fs`, `node:path`, `@shared/file-panel`)

```ts
export function createFile(root: string, name: string, seed: string): FileCreateResult
```

Four arms in `src/shared/file-panel.ts` (the repo's three-answers rule plus `exists`,
which is genuinely its own fact with its own fix):

```ts
export type FileCreateResult =
  | { kind: 'created'; path: string; mtimeMs: number }
  | { kind: 'exists';  path: string }
  | { kind: 'refused'; detail: string }   // empty name, or a path escaping root
  | { kind: 'failed';  detail: string }
```

Order, mirroring `file-write.ts:25`'s discipline:
1. `name.trim() === ''` → `refused`.
2. Append `.md` when the name has no extension (`notes/standup` → `notes/standup.md`).
3. `target = resolve(root, name)`; if it does not sit under `resolve(root) + sep` →
   `refused`. Not a security boundary (the user has a shell); it stops a `../` typo
   dropping a note outside the project.
4. `mkdirSync(dirname(target), { recursive: true })` — so `notes/` is created.
5. **`writeFileSync(target, seed, { flag: 'wx' })`** — the atomic create-exclusive. `wx`
   is load-bearing: an `existsSync` check followed by a write is a TOCTOU that clobbers a
   file an agent created in the gap. `EEXIST` → `exists`; anything else → `failed`.
6. `statSync` for the returned `mtimeMs`, which becomes the panel's first CAS token.

`seed` is `# <basename without extension>\n\n`, so the file is self-describing on disk.

Main owns the join because the renderer has no `node:path` (`file-node-model.ts:68` hand-rolls
`splitPath` for exactly this reason).

### `src/shared/file-panel.ts`

```ts
export interface FileSource {
  path: string
  /** M27. Render as prose and open in edit mode. A note IS a file. */

}
```

### Persistence — `absent stays absent`, never a spread

- `layout-schema.ts:430` `parseFileSource` — accept `prose` **only** when the raw value is
  exactly `true`; any other value is dropped *without dropping the panel* (the toolbox
  `label` precedent at `verify:layout` 143: a display convenience defaults, it does not
  drop the record).
- `layout-adapt.ts:36` (`toPanels`) and `:93` (`fromPanels`) — carry it with
  `...(p.source.prose === true ? { prose: true as const } : {})`. A spread would write
  `prose: undefined`, where `'prose' in source` then reads **true** — the exact trap
  `CLAUDE.md` records for `command`, `title` and `agent`.
- `panels.ts:646` `makeFilePanel` — same conditional copy, field-by-field.

### Rendering — `src/renderer/file/file-node-model.ts`

`buildFileNodeModel` gains `prose` from `source.prose` and returns a discriminated body so
the component branches on the **model**, not on a prop:

```ts
body: { kind: 'lines'; lines: FileLine[] } | { kind: 'prose'; text: string }
```

`editable` / `editableNote` rules are **unchanged** — a truncated prose file is still
read-only, with its own sentence. Truncation and editability stay the same fact read twice
(`:111-116`).

Keep `heading = title ?? basename` as-is (extension included — hiding it makes the file
harder to find on disk). `railLabel` in `rail-rows.ts:38` needs **no change** for the same
reason.

### `src/renderer/file/FileNode.tsx`

- Render `body.kind === 'prose'` as a single `.file-node__prose` block instead of the
  `pre[data-file-node-lines]` gutter list. Everything else — the draft, `seedRef`,
  `baseMtimeMs`, `lastWriteRef`, the reseed effect, `save(force)`, the conflict banner,
  the close/discard arming — is **untouched**. There is exactly one CAS in this app and
  this milestone does not add a second.
- Auto-enter edit mode **once**, behind an `autoEditedRef`, when `source.prose === true`
  and `model.editable`. Once, not every render: re-entering on every render would make
  Escape appear to do nothing.
- The textarea keeps `data-file-node-editor` and the `.file-node__editor` class, so
  `useNavGrid.ts:101`'s target guard covers it with no edit.

### `src/renderer/shell/rail-rows.ts` / `inspector-fields.ts`

- `railTail`'s third parameter widens from `Panel['kind']` to a display-only
  `RailTailKind = Panel['kind'] | 'note'`; `buildRailRows` passes `'note'` for a prose

- The `isFilePanel` arm at `inspector-fields.ts:394` gains one field,

### The create flow — `Canvas.tsx` + `palette/commands.ts`

- `PaletteActions.newNote(): void`; a row `panel.new-note` in the `spawn` group, **not**
  `hiddenAtRest` (it is a create verb, like `panel.open-file` at `commands.ts:677`).
  Disabled with an **exported** reason constant when there is no selected panel to root on.
- `Canvas.tsx` `beginNewNote()`:
  - root = the existing `treeRoot` value (`selectedLive?.cwd ?? selectedPanel.spec.cwd`) —
    reuse it, do not compute a second one.
  - `setInputMode({ kind: 'text', label: 'Note name', initial: 'notes/<YYYY-MM-DD>.md', submit })`.
  - `exists` → re-prompt with **`feedback: true`** (`Palette.tsx:87`) carrying "that file
    already exists"; `refused`/`failed` likewise. Never silently open the existing file —
    "create" and "open" are different acts.
  - `created` → `openFilePanel(res.path, worldCentre(), { prose: true })`. **One mint
    function**; `openFilePanel` at `Canvas.tsx:3042` gains an options argument. No new
    `window.__m27*` hook — the panels check drives the real palette row (the precedent
    `verify:panels` 147 sets for the `{ newName }` workspace move).
- Add `newNote` to the `actions` memo **and its dependency array**.

## Known limits to record rather than discover

- **A workspace switch or `Cmd+R` still takes an unsaved draft with it.** M22 records this;
  a prose panel that auto-enters edit mode makes it *more* reachable, so it must be
  restated rather than left as M22's footnote.
- **No markdown rendering**, per the non-goal above.
- **A note with nothing selected is unreachable** — the row is disabled with a reason
  rather than falling back to `$HOME`, because a note dropped in the home directory is not
  a note about anything.
