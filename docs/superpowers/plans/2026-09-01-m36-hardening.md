# M36 — Hardening for 1.0: implementation plan

Spec: `../specs/2026-09-01-m36-hardening-design.md`. Five tasks, each
check-first: write the check, run the suite, watch it fail for the right
reason, implement, run it green. Targeted suites per task; the full chain once
at the end.

## Task 2 — Unicode 11 widths

1. `npm install --save-dev @xterm/addon-unicode11@0.8.0`.
2. In `scripts/xterm-detach-entry.js`, add a third probe that imports
   `createTerminal`/`attachTerminal` from `src/renderer/terminal/create-terminal.ts`,
   opens against an attached host, writes `😀`, and records
   `term.unicode.activeVersion` and `term.buffer.active.cursorX`.
3. In `scripts/verify-xterm-detach.cjs`, add `ok('unicode.1 ...')` asserting
   `activeVersion === '11'` and `cursorX === 2`. Run: RED with `'6'` and `1`.
4. In `create-terminal.ts`, load `Unicode11Addon` and set
   `term.unicode.activeVersion = '11'` before returning. Run: GREEN.

## Task 3 — Backpressure

1. In `scripts/verify-pty-manager.cjs`, add two checks against the DIRECT
   backend: construct a manager with `flushMaxBytes: 4096`, spawn
   `/bin/sh -c 'i=0; while [ $i -lt 4000 ]; do echo "line $i padding padding padding padding"; i=$((i+1)); done; echo TC-END'`,
   collect every `pty:data` payload until the sentinel or a timeout.
   `backpressure.1`: every payload's byte length ≤ 4096 + marker length, and
   at least one payload contains `[terminal-canvas:`. `backpressure.2`: the
   last payload contains `TC-END`. Run: RED (payloads far larger, no marker).
2. In `pty-manager.ts`: `FLUSH_MAX_BYTES`, a `pendingBytes` and
   `elidedBytes` on `Session`, the head-dropping loop in `enqueue`, the
   marker in `flush`, the constructor parameter. Run: GREEN. Run
   `verify:pty` (unaffected) and `verify:pty-manager` in full.
