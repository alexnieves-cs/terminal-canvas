# v7 Act III — the visual-regression suite and the 4.0 UX audit (M148–M149): plan

Spec: `docs/superpowers/specs/2026-09-07-v7-act3-visual-design.md`. Build log:
`docs/build-log/m148-m149-act3-visual.md`. Electron-tier work on `main` alone (one
checkout); the shot harness and the visual suite share the build the chain makes.

## M148

1. Red: `verify:meta visual.1` (the script, the package.json entry outside the chain, one
   golden per declared scene, the two constants with comments). `verify:meta` 19 gains
   `verify:visual` as a named exclusion.
2. `scripts/verify-visual.cjs`: an Electron entry; spawns `npm run shot` with a scratch
   `SHOT_DIR`; reads the manifest; for each scene decodes golden and capture with
   `nativeImage` (`toBitmap()`, BGRA), compares with the two constants, writes
   `out/visual/<scene>.diff.png` on a red, prints PASS/FAIL/MISSING per scene and a tally;
   `UPDATE_GOLDENS=1` writes the goldens instead. Watchdog: 1.25× a measured run.
3. First goldens: `UPDATE_GOLDENS=1 npm run verify:visual` after LOOKING at every capture
   (that look is M149's walk); committed with the script.
4. A second run green against the goldens (the suite's own reproducibility: a scene whose
   two runs differ over budget is a flaky scene, fixed in the harness or budgeted by name in
   the scene's manifest entry — never by loosening the constants).
5. `docs/verify-suites.md`, `CLAUDE.md`'s table row, the update rule.

## M149

1. View every capture (`out/shots/*.png`), one section per scene in `docs/ux-audit-4.0.md`.
2. Fix the findings; a check per fix where cheap; declines by name.
3. The added scenes: empty/error arms where missing, `reduced-motion`, `hidpi`; each with an
   intent and a golden.
4. Re-run `verify:visual`, update the goldens the fixes changed (each in its fix's commit).
5. Critic and verifier over the act's diff, spec and the audit document.
