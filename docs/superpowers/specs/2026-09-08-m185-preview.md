# M185 — the preview reads as the app beside its code

Act III.1 of the v9 run. The [5.0 brief](2026-09-07-v9-design-brief.md)'s "Preview and media"
paragraph is the standard; the [plan](2026-09-07-v9-plan.md) gives this milestone preview
discovery, bounded project watching and reload (its M185 row) and device widths with a real
guest capture (its M186 row), consolidated here under the ledger's recorded plan amendment.

## What exists

M103's browser pane is a `<webview>` guest with a hardened partition, an address bar, and one
main-owned read through the outward gate. It has no idea what project it is pointed at, no
width but the panel's, and no way to hand a picture of itself to anything.

## What ships

**Discovery names the project and the source of its answer, and executes nothing.**
`shared/preview.ts` is the pure half: `parseListeningPorts` over `lsof -nP -iTCP -sTCP:LISTEN`
output, `parseDevScripts` over a `package.json` text (the four script names a dev server is
spelled with, in a fixed order, each with its command), `previewUrlFor(port)` and
`discoveryOf(...)`, which returns THREE states — `none` (nothing answered), `one` (a single
candidate, ready to open) and `many` (several, the person picks) — because "no answer" and
"three answers" lead to different next actions and one word for both is the wrong fix.
`main/preview-discover.ts` runs the lister over the panel's own process tree and reads the
`package.json` at its directory, both through injected dependencies; a dev script is REPORTED
with its command and never run, and a check counts the runner's calls to prove it.

**A dev script is offered, not executed.** `Start dev server` spawns the script through the
ordinary terminal path (a new panel in the project's directory), so the process is a panel a
person can see, stop and read — never a hidden child of the preview.

**Device widths are named presets, not a text field.** `DEVICE_WIDTHS` is `phone` 390,
`tablet` 834, `laptop` 1280 and `full` (the pane's own width, and the absent default). The
guest is laid out at that CSS width, centred, with the rest of the pane the panel's ground; the
address bar stays secondary to the page. The width is a layout fact on the browser record
(`device`), absent unless set, malformed dropped by name.

**Capture is a real guest screenshot saved locally, with provenance.**
`main/preview-capture.ts` refuses BY NAME first (no guest, a page that is not http(s), a guest
that answered nothing), then writes `capturePage()`'s PNG under `userData/captures` and returns
its path and the page's URL. The renderer opens it as an M181 image panel titled by the host, so
a capture is an ordinary object on the canvas — movable, exportable, deletable — rather than a
new kind. The image record carries the page it came from, so an agent handed the file can say
where it is from.

**A file-change reload coalesces and does not reconstruct the guest.** The browser store gains
one debounced reload driven by the existing `file:changed` event; the guest is reloaded through
the record it already holds, never rebuilt, so the pane does not flash and the panel's identity
is untouched.

**A failed page keeps its address and offers Retry.** The node renders the guest's own
`did-fail-load` reason beside the address with one verb.

## Doors

`preview-open`, `preview-width`, `preview-capture` and `preview-dev` each ship through the
canvas (controls on the pane), the palette (four rows) and the agent (four verbs in
`verb-table.ts` bound to `PaletteActions`). The workflow door is the same recorded omission
every v9 verb carries until the executor lands: `V9_DOORS` names the reason and the milestone.

## What this milestone does not do

No new trust path: `webviewTag`'s five hardening rules are untouched, the partition still
answers `false` to every permission ask, and `browser-read.ts` remains the only caller of
`executeJavaScript`. Capture writes a PNG to the app's own directory and sends nothing outward;
including a capture in an export is M190's explicit human review, not this milestone's.
Discovery reads `lsof` and one `package.json`; it opens no socket and starts no process.
