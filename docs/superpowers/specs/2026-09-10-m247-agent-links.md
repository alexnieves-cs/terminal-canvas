# M247 — agent → object links on the canvas

## Why
An agent reads and writes files; the canvas shows those files as objects (file, note,
checklist, sheet). Nothing today draws the connection, so "which agent touched this" is answered
by opening transcripts. M247 draws it: an edge from the agent panel to each object it touched,
carrying what it did.

## Source of truth
The agent transcripts the app already records, through the ONE place a path is read out of a
tool call: `shared/tool-index.ts` (`indexToolFiles` → `ToolTouch[]`, `toolFilePath`). Nothing is
persisted — links are derived, like `SubagentLayer`'s nodes, and a restart re-derives them from
the chat store.

Honest limits, recorded rather than faked: only chat panels have turns (a terminal agent's PTY
has none), and Codex reports shell commands without paths, so neither produces links.

## The mapping (pure: `shared/agent-links.ts`)
`agentLinks({ agent, cwd, touches, objects, drafts })` → `AgentLink[]`:
- **kind** from the tool name: `Write`, `Edit`, `MultiEdit`, `NotebookEdit` → `wrote`; `Read`,
  `Grep`, `Glob`, `NotebookRead`, and anything unknown → `read` (the conservative word: claiming
  an unknown tool wrote a file is a false alarm on the review gate).
- **draft** when the object is a sheet whose pending draft names this agent (`draft.by`).
- **precedence per (agent, object)**: `draft` > `wrote` > `read` — one edge per pair, the
  strongest fact.
- **path matching**: a relative path resolves against the agent's cwd; comparison normalises
  `/private/var` ↔ `/var` the way `matchReviewPath` already does. **A path with no object on the
  canvas is ignored** — the canvas draws what is on it.

## The store (`renderer/canvas/agent-links-store.ts`)
The `useEdgeActivity.ts` shape: a snapshot per AGENT panel id, replaced only when its content
changes; one layer-wide version for the layer. Fed from the chat store. **Never
`registry.version()`** — a busy agent emits tool calls several times a second.
`forgetAgentLinksFor(id)` at every panel-removing call site (the five that clear
`clearAgentState`); a link to a closed OBJECT drops at derive time as well (the
`buildLinkSegments` double prune).

## Rendering (`renderer/canvas/AgentLinkLayer.tsx`)
An SVG inside `.world` beside `LinkLayer`, so it pans and zooms with the panels; geometry from
`link-geometry.ts` (`linkAnchors`, `linkPath`, `linkControls`) — the same curve, never a second
one. `read` is thin and dashed, `wrote` solid, `draft` the accent with a badge; **clicking a
draft badge opens that draft's review** (focus the sheet, select its first draft cell).
`pointer-events: none` on the layer; only the badge consumes a click.

**LOD** (`card-detail.ts` names what a card SHOWS — `tail` is NEAREST): `tail` shows every link
with its word; `summary` bundles to one link per (agent, kind) toward the object nearest the
agent, with no words; `block` hides them. `agentLinkPlan(links, detail)` holds that decision.

## Toggle
`agent-links on|off|toggle`, persisted as a setting; four doors: palette `canvas.agent-links`,
the canvas's view control, `tc plan agent-links off`, and an action node with the same line.

## Checks (`verify:agent-links`, plain node)
The mapping (each kind, precedence, relative paths, the `/private` suffix, a path with no object
ignored, a non-chat agent yields nothing); the store forgets a closed panel and never notifies an
unaffected agent's subscriber; a source scan that every site calling `clearAgentState` also
calls `forgetAgentLinksFor`; `agentLinkPlan` per tier; the toggle's doors through `verify:verbs`.
