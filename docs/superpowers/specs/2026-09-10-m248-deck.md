# M248 — deck: slides backed by Markdown, per-slide draft review, PDF export

A deck is a Markdown file shown as slides. It is `kind: 'file'` with an optional
`source.deck: DeckView`, exactly the M244 checklist shape — NOT a new panel kind — so it
inherits the file read/watch, main's compare-and-swap write, `isTerminalPanel`'s exclusion,
tiering, selection and undo. A person's own edits write to the file directly (through the
CAS guard); an agent's or a workflow's edits never do.

## The file is the deck

- Optional Marp-style front matter: a leading `---` … `---` block, kept verbatim, never a slide.
- Slides split on a line that is exactly `---`. Not inside a fenced block (``` or ~~~, the
  fence's LENGTH tracked, so a 4-backtick fence holding a 3-backtick one is still one fence),
  not inside the front matter. `***` and `- - -` are thematic breaks, not slide breaks.
- Every slide carries its source span `{start, end}`; untouched slides are never
  re-serialised, so a file with no change is byte-identical.
- Speaker notes are `<!-- notes … -->` comments: pulled out of the rendered body, kept in
  the source.

## Per-slide draft review

`src/shared/draft-review.ts` is GENERIC (it is M246's planned API, built here first; the
sheet branch adopts it): `DraftItem<V> = {id, old, new}`, `Draft<V> = {baseHash, by?, at,
items}`, `diffItems`, `keep`/`discard` → `{apply, remaining}`, `draftState` →
`none | pending | conflict`. Its checks run on non-slide items.

The deck adapter aligns old and new slides by an LCS on each slide's source hash, so
inserting slide 2 of 5 is ONE added item, not four changed ones. Item ids are what a person
types: the proposal's slide number for a changed or added slide, `r<n>` for a removed one.
`applyKept` splices only the kept items into the current disk text; keeping against a disk
that no longer hashes to the draft's base is a named conflict (the file and the slides),
never a merge.

`deck-edit` / `deck-write` arriving through the agent door (`tc plan`) or a workflow action
node STAGE into `DeckView.draft`; the same verbs from the palette write. `deck-review keep`
through those doors is refused by name (a draft is reviewed by a person); `discard` —
withdrawing a proposal — is allowed there. A TEAMMATE's plan may do none of the three
(`TEAMMATE_REFUSED_VERBS`, the plan's rule for editing and review verbs). `deck-present` from
a door is refused (a full-window overlay takes the person's keyboard). The card, header,
Present and PDF always read the file; a proposal is only ever shown as a proposal.

## Surfaces

- Card (rest): the current slide as a thumbnail; the header keeps "slide N of M" and, only
  when above zero, "3 slide changes". A deck therefore KEEPS ITS HEADER under the M236
  frame rule.
- Filmstrip (contextual): absolutely positioned over the bottom of the body, opacity 0 → 1
  on `.pf:hover` / `:focus-within`; it never changes the body's box. Changed slides marked.
- Edit: split source and preview through the same renderer; saves through the CAS write,
  a refusal named "changed on disk". Subscribes to `edit:copy/paste/undo`, and
  `deckFocused()` joins `shouldIgnoreKeys`.
- Presenter: a fixed full-window overlay portalled to `body`; never resizes a panel. Arrow
  keys, Space, PageUp/PageDown and Escape captured only while it has focus; notes pane
  toggles.
- Images: a relative path next to the `.md` through `image:read`; inserting one goes
  through `asset:choose` → `asset:put` and writes the stored path. `http(s):` is never
  fetched — a named placeholder "remote image not loaded".

## PDF

`export:deck-pdf` (a new invoke channel). `src/main/deck-pdf.ts` with injected deps: a
hidden sandboxed `BrowserWindow` (javascript off, no preload, offscreen) prints a generated
page, one 16:9 `@page` per slide, images inlined as data URLs, every slide's text through
`outward()` (no new `redactSecrets` caller). Save dialog, then an atomic write.

## Portable

Export carries `deck: {}` — never the draft or the current slide. Import is inert.
