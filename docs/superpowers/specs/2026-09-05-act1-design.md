# Act I — control and autonomy (M96–M99)

**Status:** design, 2026-09-05. **Branch:** `m96-verbs` (one branch, one merge for the act).
**Kind:** runtime + surface. **Briefs built against:** 1.x principles 7 (three states), 9 (a
disabled row names the fix); 2.0 principle 13 (`Canvas.tsx` owns the gesture, the pure module
owns the rule). **Thesis sentence:** the app has one closed vocabulary of verbs with a
destructive flag and a confirmation gate; an agent can run bounded on its own; a permission
can be granted for a session; and a backend is a row in a table, never a name a consumer
switches on.

## M0, recorded

- The chain is green on clean `main` (the panels suite alone: 303/303 after a watchdog red under
  spike load). The `<webview>` spike passed both halves (Act II's spec carries the numbers).
- **No ACP-speaking CLI is installed** (`claude` 2.1.261, `codex` 0.153.4; no `gemini`, no
  `claude-code-acp`/`codex-acp`). M99 is the registry alone; see "ACP, declined" below.
- The timer trigger is armed end to end in `main/index.ts`; M101 is a surface (Act II).

## M96 — the verb table and its guardrails

### The table (`shared/verb-table.ts`, pure)

`VERBS: readonly VerbDef[]` — a closed data table. Each `VerbDef` carries `id`, `label`, the
`args` it takes (name, kind `panel | text | preset | setting | value | key`, required), a
`destructive` boolean, the `refusals` it can answer with (named reason ids, each a sentence with
its fix), and `target`: what it acts on (`canvas`, `panel`, `agent`, `setting`). The verbs are
derived from `usePaletteActions`' members and M81's `CanvasModel`:

| verb | args | destructive | note |
|---|---|---|---|
| `focus` | panel | no | `goToPanel` |
| `spawn` | preset, text? (cwd) | no | `spawnPreset` — main resolves an absent command (M5b) |
| `type` | panel, text | no | C0 stripped; an agent panel only (guardrail 3, 4) |
| `submit` | panel | no | Enter, its own verb, confirmable |
| `send` | panel, text | no | a chat's composer send |
| `restart` | panel | no | `restartPanel` |
| `set-setting` | setting, value | no | `planWritable` keys only (guardrail 1) |
| `read` | panel | no | the outward gate (guardrail 2) |
| `close` | panel | **yes** | `closePanel` — a dispose |
| `reset-canvas` | — | **yes** | `resetCanvas` |
| `discard` | panel | **yes** | `review:discard` |
| `remove-worktree` | key | **yes** | `worktree:remove` |
| `interrupt` | panel | no | a chat's interrupt; Ctrl-C into an agent terminal |
| `start`, `lock`, `unlock`, `pin`, `unpin`, `maximise`, `restore`, `tidy`, `zoom-fit`, `workspace`, `review` | — | no | the M92/M56 verbs, one member each |

**There is no `kill`.** A process's lifetime is its panel's (the two-lifetimes rule) and
`pty.kill` keeps exactly two callers by design; `close` is the dispose, `interrupt` the stop.
`table.1` asserts the verb is absent.
| `run-template` | key | no | `instantiateTemplate` |

**The closure rule is the milestone's long-term value:** `EXCLUDED_ACTIONS` names every
`PaletteActions` member the table deliberately leaves unreachable, with a reason each (a
`begin*` opens UI; `toggleSetting` is `set-setting`'s door; `answerApproval` is M98's door,
never a plan step). `verify:verbs closure.1` asserts every member of the `PaletteActions`
interface (read from `commands.ts` as text — the interface is the authority) is in the table's
`actions` mapping or on the excluded list. A member on neither fails the build, so a verb a later
milestone adds cannot become reachable silently.

### The plan (`shared/plan.ts`, pure)

A `Plan` is data: `steps: PlanStep[]`, each `{ verb, args, confirm?: { reason } }`.
`buildPlan(input: PlanInput[], facts: PlanFacts)` validates against the table and returns
`{ kind: 'plan', plan } | { kind: 'refused', reason, fix }`. Refusals by name: unknown verb;
a missing required argument; a `panel` argument naming no panel in `facts`; `type` into a panel
whose kind is not an agent (`facts.panels[i].agent` is what `AGENT_CAPABILITIES` keys on — a
plain shell, a file, a review node refuse; **never** a string check on the command);
`set-setting` on a key without `planWritable`; a `key` that names nothing. A destructive step
is not refused — it is given its confirmation step (`confirm: { reason }`), and `runPlan`
refuses to execute a destructive step whose `confirm` is missing or unacknowledged. `type`'s
text is passed through `stripControl` (every C0 byte and DEL removed; `\r`/`\n` included — Enter
is `submit`). `parsePlanLine('close n3')` turns the palette's typed line into `PlanInput`s.

`PlanFacts` is derived from M81's `ControlCanvasModel` plus each panel's agent kind — the same
words `tc status` answers with.

### The outward gate (`shared/outward.ts`, pure)

`outward(text, source)` → `{ text, redacted, note }`: `redactSecrets` applied, a note saying
where the content came from and how many placeholders were written. The `read` verb, M97's
prompt context, export and M103's browser read all pass through it. `verify:verbs gate.1`
plants a GitHub token in a panel's scrollback (the real `scrollback-log` under a temp dir) and
asserts the plan's read hands back a text that does not contain it and a count of one.

### Settings (`shared/settings-schema.ts`)

`SettingDef.planWritable?: true`, set on the cosmetic and attention keys only: `agent.glow`,
`agent.bell`, `attention.notify`, `attention.sound`, `appearance.theme`, `agent.edgeIndicators`,
`canvas.minimap`, `placement.snap`, `files.showHidden`, `terminal.fontSize`. Not on
`agents.maxConcurrent`, `agents.budgetUsd` (a plan that raises its own ceiling has none),
`vault.root`, `session.keepOnQuit`, `scrollback.persist`, the `restore.*` and `shell.*` keys.
`verify:verbs settings.1` asserts the two ceilings and the vault root are refused and one
cosmetic key is allowed.

### The surface

One palette row, `Run a verb…` (section `canvas`, always present), enters text mode with the
label `verb arguments — e.g. focus n3, type n3 hello, close n3`. The typed line is parsed and
built against the live facts; a refusal re-prompts with `feedback` (the palette's own refusal
idiom) naming the reason and the fix; a plan with no confirmation step runs; a plan with one
enters the palette's `confirm` mode naming the destructive verb and its target before running.
Every step reports in the canvas's own state vocabulary (the row's feedback line reads
`ran close n3 · 1 step`). `usePaletteActions` gains three appended members (`beginRunVerb`, and M97's
`startAuto`/`stopAuto`), all on `EXCLUDED_ACTIONS`, so `Palette`'s memo identity is untouched.

### Deliberately not in this milestone

- **No natural-language resolver.** A `main/resolve-utterance.ts` over M71's seam would need
  a system prompt, an ambiguity arm and recorded-stream fixtures; nothing downstream reads it —
  M97, M101 and M102 read `destructive` and the plan shape. What it would take: a headless
  session per utterance with the verb table serialised into its system prompt, a JSON answer
  parsed into `PlanInput[]`, and `buildPlan` doing exactly what it does here. Deferred to a
  later run.
- **No voice, no `Transcriber` seam.** Transcription is a network service (constraint 1) or
  the OS's dictation (a keyboard, not an API). No orb, disabled or otherwise.

### Failure modes, each with its check

| Failure | Check |
|---|---|
| An action reachable through no table row and no excluded entry | `verify:verbs closure.1` |
| A plan writing a ceiling or a credential-adjacent key | `verify:verbs settings.1` |
| A token leaving through a plan's read | `verify:verbs gate.1` |
| `\r` typed into a shell | `verify:verbs type.1` (C0 stripped; `submit` separate) |
| A typed step aimed at a shell, a file, a review node | `verify:verbs type.2` (kind via `AGENT_CAPABILITIES`) |
| A destructive step run without its confirmation | `verify:verbs destructive.1` |
| The row hidden, or a refusal with no fix | `verify:palette verbs.1` |

## M97 — Auto, a bounded autonomous run

### The modes (`shared/auto.ts`, pure)

`AUTO_MODES`: `complete` (finish the task in the conversation), `harden` (find and fix the silent
failures), `review` (read, report, change nothing), `custom` (the user's task). Each is a
prompt vocabulary — an opening prompt, a continuation prompt, the completion marker the agent
is told to print (`AUTO-DONE`) — and a `turnLimit` (8, 8, 4, 8). A mode is validated as a plan:
`validateAutoMode` runs its steps (a `send` per prompt) through `buildPlan`, so a mode holding
a destructive verb without its confirmation is refused by name — `verify:verbs auto.1`.

### The runtime (`main/agent-session.ts`)

`AgentSessionManager.startAuto(id, { mode, task?, limit })` sends the opening prompt through the
ordinary `send` (so it queues behind `agents.maxConcurrent` and is refused past `agents.budgetUsd`
by name, unchanged). On every `result` for that session main counts one auto turn and decides:
the last assistant text carries the marker → `done`; the count has reached the limit → `stuck:
limit`; otherwise the continuation is sent. `stuck: permission` when the turn ends with a request
nobody answered inside the grace; `stuck: exit` on a non-zero exit; `stuck: budget` on a refusal.
**The counter is main's, read live like M82's ceilings** — the renderer's chip is a projection
of `auto` events and can never move the stop. `verify:agent-session auto.1` replays more turns
than the limit and asserts exactly `limit` sends left the manager and the stuck reason is
`limit`; `auto.2` asserts the marker ends the run early as `done`. `stopAuto(id)` ends it as
`stopped` (an interrupt if a turn is in flight).

Events: `{ type: 'auto'; mode; turn; limit; state: 'running' | 'done' | 'stuck' | 'stopped';
reason? }` on the same batched channel.

### An Auto run is a run

`useRuns` records it: the auto start begins a run whose component is the one panel, named
`auto · <mode>`, and the end seals it with its cost by M79's rule — listed in the Workspaces pane
with `Run again` refused by name for a chat root, exactly as M79 refuses it today.

### The surface

The chat's chrome gains a live chip after the state pill: `auto · complete · 2/8` with a ring
while running, resolving to `done` or `stuck — limit reached` with a labelled `dismiss`. The
modes are palette rows on the captured chat (`Auto: Complete`, `Auto: Harden`, `Auto: Review`,
`Auto: Custom task…` — text mode for the task — and `Stop auto`), each present and disabled by
name for a terminal, a codex chat without the marker contract (allowed — codex reads the same
prompts), or a chat already running. The chrome's `auto` word-verb opens the palette on those
rows (the rename verb's idiom), so no second menu is grown.

## M98 — `Allow for session`

`main/approvals.ts` gains the grant: `grant(id, toolName)`, `granted(id, toolName)`,
`revoke(id)`, keyed by session **and** tool, held in memory, **never written anywhere**, cleared
on dispose (and on `revoke`). The manager takes a `preAnswer?: (id, toolName) => boolean` dep;
a `permission-request` the tracker has granted is answered `allow` immediately and emitted as
`permission-auto-allowed` (the transcript shows a quiet row; attention never lights). The IPC
answer request grows `scope?: 'session'`; main grants THEN answers through the one
`answerPermission`. Every surface still answers through the one `agentSession.answer` verb —
the inline card renders `Allow` / `Allow for session` / `Deny`; the popover, pane, palette and
summary tier keep their two.

Codex cannot ask (`AGENT_CAPABILITIES.codex.headless.permissions === false`): the inspector's
Detail carries a `Session grants` field for every chat — `none`, the tool list with `Revoke`,
or for codex the named reason `codex asks no permission here — its sandbox policy decides` on a
disabled control, never a missing one.

Checks: `verify:agent-session grant.1` (a granted tool is answered without an event reaching
the renderer's pending set, a different tool still asks, dispose clears, the grant survives an
exit-and-resume of the same session but never a new manager); `grant.2` reads `layout-store.ts`,
`agent-transcript-log.ts` and `approvals.ts` as text and asserts no grant is written.

## M99 — the backend registry; ACP declined

### The registry (`shared/agent-backends.ts`, `main/backend-adapters.ts`)

`BACKENDS: Record<AgentBackend, BackendDef>` — the ONE table: `id`, `label`, `binary`, the
capabilities M90 scattered (`resumes`, `interrupts`, `images`, `reportsCost`, `asksPermission`,
`terminalDoor`, `oneProcessPerTurn`, `closeStdin`, `adoptsThreadId`), and every named reason
(`noCli`, `noInterrupt`, `noImages`, `noTerminal`, `noPermissions`). `AGENT_CAPABILITIES.headless`
is derived from it, not duplicated. `main/backend-adapters.ts` maps each id to its argv builder
and line parser (the process half lives in main because the claude builder does). `BACKEND_IDS`
is the spawn sheet's list: one `chat with <label>` row per backend, disabled with `noCli` when
the binary is absent — never hidden. The sheet's model field suggests the models live sessions
have REPORTED (`snapshot.model`), not a vendor list.

**No consumer switches on the name.** The manager reads `BACKENDS[session.backend].oneProcessPerTurn`
etc.; `chat-model.ts` reads the reasons; the by-name copy sites use one `carryBackend(chat)`.
`verify:agent-session registry.1` greps `src/` for `backend\s*[!=]==\s*'(claude|codex)'` and
`case '(claude|codex)'` and asserts the set of files is exactly `{ shared/layout-schema.ts
(the parser), shared/agent-backends.ts }`.

### ACP, declined by name

No ACP-speaking CLI is on this machine (M0), so the protocol cannot be measured, and an adapter
against an unmeasured protocol is what M71's and M90's recorded streams exist to prevent. What
it would take: an ACP agent installed (`gemini --experimental-acp`, or the `claude-code-acp`
adapter); three streams recorded (`initialize` → `session/new` → `session/prompt` with a tool
call, a permission request and a resume) into `scripts/fixtures/agent-session/acp/`; a small
JSON-RPC layer over the manager's line seam (ACP is bidirectional — `session/request_permission`
is a request the host answers by id, where claude's is a line the host writes); an
`acp` row in `BACKENDS` with `adoptsThreadId` and `asksPermission`. The registry makes that row
the whole cost.

## What the act must not break

`registry.version()` carries nothing new; the M61 identity rule on both process doors; the
credential store's three readers; `usePaletteActions` as one `useMemo`; the `agent:state`
channel's two words.
