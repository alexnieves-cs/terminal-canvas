# Act III — the polish that pays (M104–M107)

**Status:** design, 2026-09-05. **Branch:** `m104-lineup` (one branch, one merge for the act).
**Kind:** surface. **Briefs built against:** 1.x principles 3 (a row that begins with a path is
wrong), 6 (every control says what it is), 7 (three states), 9 (a disabled row names the fix);
2.0 principle 13. **Thesis sentence:** the interface tells you what is happening without you
asking — before you commit resources, while agents work, and when discovery fails.

Four milestones over largely disjoint files, fanned out as two tracks: A = M104 (the spawn
sheet, `template-model.ts`, `shared/templates.ts`) → M106 (`PanelFrame.tsx`, `styles.css`, the
workspace menu, the far-view renderer); B = M105 (`rail-rows.ts`, a new store, `Dock.tsx`) →
M107 (`env-report.ts`, the inspector's Changes section, the chat header).

## M104 — Before you commit resources: the lineup preview

`shared/lineups.ts`: four LINEUP presets — `Solo` (one agent seat), `Pair` (an agent and a
plain shell), `Workbench` (an agent, a shell, a browser at `localhost:3000`), `Swarm` (three
agents in worktrees and a shell) — each a list of SEATS: `{ role, kind: 'agent' | 'shell' |
'browser', command?, url?, worktree?: boolean }`. A lineup is a template of the shape M80 already
instantiates, so instantiation is M80's path; what is new is the SHEET before it: how many
sessions will open, each seat's role and kind, the directory, and — against `agents.maxConcurrent`
read live — the line `N of these will queue behind the ceiling of M` BEFORE anything is minted.
Confirm mints; Escape mints nothing.

**Seats that are not agents.** A shell seat is a terminal with a command; a browser seat is an
M103 pane at its url. When launching into worktrees, ONLY agent seats get a lane — browser and
shell seats stay in the repository checkout, because a browser seat in a worktree points at a
directory the dev server was never started in. `lineupPlan(lineup, { worktrees })` is pure and
`verify:palette lineup.1` asserts the lane rule; `lineup.2` asserts the ceiling line's arithmetic.

## M105 — The rail says what is happening

`renderer/session/last-line-store.ts`: a module-level store subscribed PER PANEL ID (never on
`registry.version()`), holding per panel `{ lastLine, unread, finishedAt }`. **The last line is
the transcript's last complete text block** — for a chat, `lastAssistantText`; for a terminal
running an agent, the last OSC-133-delimited command's last output line is NOT available in the
same words, so a terminal row shows its state tail as today and the last line only for chats
(stated: the content is the same in both front-ends of a CONVERSATION, and a terminal's
scrollback is not a conversation). `unread` is set when a chat's turn ends while the panel is
not focused (`onChatTurnEnd` with `focusedIdRef !== id`) and cleared on focus. The store is
cleared at every panel-removing call site, as every sibling is.

The rail's rows become two lines: the label and state on the first, the last line (one line,
ellipsised from the RIGHT — it is prose, not a path) on the second, with an unread dot before
the label. The dock gains two capsules beside the attention badge: `N quiet` (idle/asleep
chats) and `N live` (working), from the same store. `verify:rail lastline.1` (the row model),
`verify:registry lastline.1`-shaped store check in `verify:rail` (subscribe by id, clear on
remove, unread set only when unfocused).

## M106 — Header discipline, and the workspace's two verbs

**Never print a name that truncates to `Revie…`.** `PanelFrame` gains ONE rule for every kind:
the chrome leads with the liveness dot plus the kind mark; the title is `text-overflow:
ellipsis` with a `min-width: 0` and the FULL title lives in the `title` attribute and at the top
of the frame's `⋯` menu (a small popover on the chrome — the one menu the act adds, which M97's
Auto rows and M92's marks also join); the header's middle READS ON from the mark (a browser's
address, a chat's token count) and terminal and file panes leave it empty; the verbs never
shrink (`flex: 0 0 auto`), so what gives is the title, whole words first. Enforced in
`PanelFrame.tsx` and `styles.css` once, for all kinds — not per kind. `verify:styles header.1`
pins the CSS rule; `verify:panels header.1` measures a frame at 320px with a long title and
asserts the verbs are all visible and the title carries its full text in `title`.

**Tidy Panes and Flip Terminals** live in one `Workspace` menu (main's menu, `menu.ts`) and as
palette rows. Tidy is M40's `tidyPanels`. Flip turns every terminal over to show the work title
large with agent and role beneath — **M57's semantic-zoom far view invoked deliberately**: a
`flipped` set in Canvas hands `detail: 'summary'` to those frames through the existing
`card-detail-context`, so the far-view renderer is reused and no second one is grown. Flip
respects M92's marks (a locked panel does not move — nothing moves; a maximised one flips in
place) and is a view state, never persisted. `verify:panels flip.1`.

## M107 — The app explains itself

**Changes refresh on turn end.** The inspector's Changes section (`useInspectorDetail.ts`)
re-asks `review:panel` when `onChatTurnEnd` fires for the selected chat (M77 captured the
baseline at `agent:create`; the trigger was the missing piece). **The thread header carries
folder + git branch + engine + model**: the chat chrome's middle reads `api · main · claude ·
opus`, the branch from M86's `git:status` (which already names the repository), the model from
the session's snapshot. `verify:rail header.1` (the pure line builder).

**Agent discovery that explains itself.** `env:report` gains `probe: { shells: string[]; folders:
string[]; outcome: 'found' | 'not-found' | 'no-answer'; detail?: string }` — which shells were
asked (`$SHELL -lic`, `/bin/zsh`, `/bin/bash`), which folders were checked (the PATH entries),
and the DISTINCTION THAT MATTERS: a shell that timed out or exited non-zero is `no-answer` (`the
shell didn't answer — a slow or prompting ~/.zshrc; try …`), never `not-found`. Three states,
never two. The launcher and the environment row point at the `~/.zprofile` fix and offer `Check
again` (a re-probe through `env:report`). **This is a defect, not a feature**: the repository's
own three-state rule broken by a surface it ships, written up as such in the log.
`verify:file env.1` over an injected probe (a timeout → `no-answer`).

## Declined / deferred by name

- A terminal's "last line said" from scrollback (M105): the same content is not available in the
  same words for a terminal; a chat's is. Recorded rather than faked.
- Per-kind header rules: the frame rule is the whole point; a kind that needs its own is a
  finding for the critic.
