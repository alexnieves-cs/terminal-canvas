## What a note is, and what this milestone changes

A note is a Markdown FILE: a `kind: 'file'` panel whose source carries `prose: true`
(`src/shared/file-panel.ts`). Its editor has been a `<textarea>` over the whole file since
M27, saved through `file:write`'s mtime compare-and-swap. This milestone adds two things and
changes nothing about what a note is:

1. A **Rich** mode beside the existing **Source** mode, inside the same draft. Rich edits
   produce the same draft string the textarea produces; the Save button, `⌘S`, the conflict
   banner, the dirty marker and the CAS token are FileNode's, unchanged. Source stays the
   default mode, so every existing reader of `data-file-node-editor` keeps its surface.
2. **.docx import**: a Word file becomes a NEW `.md` beside it, opened as a note that is
   unreviewed until a person reads it, with what the conversion dropped named and counted.

## Why no editor library

ProseMirror, TipTap and Milkdown each parse Markdown into their own schema and serialize the
schema back out. That round trip is where they normalize: `*` bullets become `-`, emphasis
`_x_` becomes `*x*`, long lines are re-wrapped, characters are re-escaped, reference links are
inlined, HTML blocks that the schema has no node for are dropped or escaped, trailing
whitespace and CRLF are lost. A note is a file other tools (and agents, and git) also read, so
a save that rewrites lines the person never touched is a diff nobody asked for — and on an
agent-edited note it is a diff that looks like the person's. They would also be the largest
dependency in the renderer, and the renderer's CSP and the brief both argue against it.

**Instead: blocks with source spans (`src/shared/md-blocks.ts`).** A note is cut into blocks
that tile the file exactly — every byte belongs to exactly one block, blank runs included —
so concatenating the blocks' `source` IS the file. Kinds: `heading` (ATX), `paragraph`,
`list`, `table` (GFM pipe), `image` (a paragraph that is only `![alt](src)`), `code` (fenced),
`blank`, and `raw` for everything the rich editor does not model. A `raw` block carries a
**name**: `HTML block`, `footnote`, `reference link definition`, `setext heading`,
`block quote`, `front matter`, `nested list`, `indented code`, `thematic break`.

Save is block-wise by construction: an untouched block writes its original bytes, and an edited
block is re-serialized from its own model with its own line ending. The round trip with no
edits is byte-identical for every input, not by care but by construction (`notes.roundtrip.1`
over a corpus that includes CRLF, a missing final newline, trailing whitespace, tabs, setext,
HTML, reference links and front matter).

**Never silently rewritten.** Two refusals, both named:
- A `raw` block is shown as its source with a badge — "HTML block — edit as source". The rich
  editor never re-serializes it; a person may edit its bytes in a per-block source box, and
  those bytes are exactly what they typed.
- An editable block whose content carries something its model cannot represent (inline HTML,
  a footnote reference, a reference-style link, a hard line break) opens in source for that
  block with "can't edit inline HTML in rich mode". And every rich edit is checked by
  re-parsing what it would write: if the result would not read back as the same kind with the
  same content (a paragraph that starts with `# `, text with a blank line that would split the
  block, a list item that would become a nested list) the edit is refused with the reason and
  the draft is unchanged (`notes.edit.1`).

The editing surface (`src/renderer/file/RichNoteEditor.tsx`): per-block `contentEditable`
(plaintext) for paragraphs and headings, showing the block's inline Markdown while it is being
edited and rendered inline at rest (the app's own `parseInline`); a list editor (one field per
item, add/remove, task checkboxes, the original marker kept); a table grid editor for GFM
pipe tables (cells, add row, add column; the delimiter row kept verbatim while the column count
holds); link insertion over the selection; image insertion through `asset:choose` →
`asset:put`, writing `![](<stored path>)`. Undo/redo are the editor's own history of draft
strings. The editor subscribes to `edit:copy`/`edit:paste`/`edit:undo`/`edit:redo` itself and
acts only while it holds `activeElement` (ChecklistNode's shape), and `noteEditorFocused()`
joins `shouldIgnoreKeys` so a `⌘V` aimed at a note never reaches the focused terminal.

## .docx import

**Dependency audit.** `mammoth` **1.12.2** (published 2026-08-28), pinned exact in
`dependencies`; `jszip` **3.10.2** pinned exact beside it (it is mammoth's own dependency;
declared so the loss report's reader is ours by name rather than by hoisting). Recorded with
the commit: `npm audit --omit=dev` after adding both — see the ledger line for the output. Both
are main-process only: `externalizeDepsPlugin` keeps them out of the main bundle, the renderer
never imports either. mammoth's transitive set (`@xmldom/xmldom`, `lop`, `bluebird`,
`underscore`, `xmlbuilder`, `base64-js`, `argparse`, `dingbat-to-unicode`,
`path-is-absolute`) is plain JS with no install scripts and no native code.

**Conversion runs in main** (`src/main/docx-import.ts`, deps injected so `verify:notes` drives
it in plain node):
- The path must be absolute and end in `.docx`, and the file is refused by name over
  `DOCX_MAX_BYTES` (20 MB) from `stat`, before it is read.
- `mammoth.convertToHtml` with an image handler: each image's bytes go to `putAsset`
  (`asset-store.ts`) and the HTML references the stored path. An image the store refuses is
  counted in the report, never silently missing.
- `src/shared/html-to-md.ts` maps mammoth's small vocabulary (`p`, `h1`–`h6`, `ul`/`ol`/`li`,
  `table`/`tr`/`td`/`th`, `a`, `strong`, `em`, `img`, `br`, and mammoth's footnote list) to
  Markdown with a tag scanner sufficient for mammoth's well-formed output — no DOM in main.
  mammoth's own Markdown writer is deprecated upstream and is not used.
- **Loss report, by name and count**, read from the OOXML through `jszip`: `w:comment`
  in `word/comments.xml`; tracked changes `w:ins`/`w:del`/`w:moveFrom`/`w:moveTo` in the body
  (mammoth shows insertions and drops deletions, so the text is as-if-accepted — the report
  says so); complex tables (a top-level `w:tbl` holding `w:gridSpan`, `w:vMerge` or a nested
  `w:tbl` — a pipe table cannot say "merged"); text boxes (`w:txbxContent`); footnotes and
  endnotes (moved to the end as a list); headers/footers with text; images not kept; and
  mammoth's own `messages`. The sentence is "Dropped: 2 comments, 2 tracked changes, 1
  merged-cell table" — a zero is never stated, and a clean import says nothing was dropped.
- The output is a **new** file via `createFile` (`wx`, refuses rather than overwrite): `<name>.md`
  beside the docx, else `notes/<name>.md` beside it, else the `exists` arm naming the path.
  The docx is only ever read (`docx.readonly.1` compares its Buffer before and after).

**Channel.** `docx:import` (invoke), added to `ipc-contract.ts` first. With no path, main opens
the system's own chooser filtered to `.docx`; a cancel is `cancelled`, not a refusal.

**The import gate — inert until a person looks.** The new panel carries
`FileSource.imported: { from, dropped }` with `reviewed` unset. While unreviewed: the note does
not auto-enter its editor, ✎ is disabled with "Read this imported note before editing or
sending it", the body shows that sentence and an **I've read it** control, and the agent
`read` verb refuses the panel by the same sentence. The loss report sits in the header's
contextual layer (opacity 0 → 1), and in the import's own result. `reviewed: true` is what a
person's click writes. A portable export carries `imported` without `reviewed`; a portable
import strips `reviewed` from a hostile file — the checklist's `accepted` precedent
(`checklist-session.ts`, `portable.ts`), applied to prose.

**Four doors for `import-docx`:** canvas — drop a `.docx` on the canvas (the same `dropPath`
arm pictures use); palette — `note.import-docx`; agent — `tc plan import-docx <path>`;
workflow — an action node whose line is `import-docx <path>`. Refused to teammates
(`TEAMMATE_REFUSED_VERBS`): a teammate's plan does not choose which files this app reads and
where it writes.

## Non-goals, named

- No WYSIWYG inline rendering while typing: a paragraph shows its inline Markdown while it has
  the caret and renders at rest. This is the price of never normalizing.
- Nested lists, block quotes and HTML are editable only as their source.
- No export back to .docx.
- A merged-cell table is imported with the merged cell's text in its first column and empty
  cells after it; the report names it, the Markdown cannot.
