# M206–M208 — D10 hierarchy, navigation and contextual controls

## Decision

D10 is a reconciliation, not a new shell. The current material system, pane ownership, object
models and four-door verbs remain authoritative. We will remove category errors and persistent
competition while preserving every existing action route and named refusal.

The four density layers are the acceptance model: rest shows identity and one state; contextual
surfaces show the next action, blocker and related work; the inspector shows configuration,
provenance and outcomes; logs, metrics and history stay in detail.

## M206 — shell and category language

- The navigator's credential/service page is **Connections**, not Integrations. Browser, watcher
  and memory are authored objects, not integrations.
- Panel groups are Agents, Files, Reviews, Work, Workflows and Capabilities. Browser and memory
  sit with Files as things a person reads; watcher sits with Workflows; Toolbox and Skill sit
  with Capabilities. Unknown future kinds land in Capabilities and never disappear.
- Skills remains the reusable capability inventory and assignment surface. Toolbox remains the
  selected folder/chat's contextual inspection; the explanatory copy names that distinction.
- Vault keeps its name because it is the Markdown-note collection. Canvas objects use sticky,
  text and frame throughout; no persisted discriminator is renamed.

## M207 — inspector and contextual controls

- The pinned inspector bar shows a compact primary/context row. Restart is primary only for a
  terminal; chat approvals lead only while pending. Object-generic layout actions remain in an
  overflow disclosure instead of a permanent generic grid.
- Every unavailable capability remains reachable and carries its existing reason. Disclosure
  changes presentation only; it does not create a second action implementation.
- Metrics remain in Detail/Machine and cost/history remain in Work. Toolbox stays in Tools.

## M208 — workflow, far view and audit closure

- Workflow Run remains the one filled action. Trigger, Stop, Save, Delete and Build with AI move
  to a contextual disclosure; disabled actions retain title/reason text, revealed on hover/focus.
- The graph gets the available body before explanations. Block metadata remains sentence case
  with a middle dot. Far/summary surfaces keep title, kind and one meaningful state; small
  secondary text may drop whole but never clip mid-word.
- Backlog #86 and #88 are reconciled item by item. Already-fixed items are cited rather than
  rewritten. Remaining deterministic fixture, layout and copy defects are fixed red-first.

## Boundaries

No schema migration, new IPC family, duplicated runner, styling dependency, class rename or
change to session ownership. Existing `.panel__*` and `*-node__*` aliases remain. Both themes,
compact/wide layout, keyboard focus, hover and reduced motion are part of the visual gate.

## Acceptance

The next action is visually singular, object identity remains clear, and capabilities are
discoverable without a permanent wall of generic controls. `npm run verify`, intentional visual
goldens and the packaged gate close the act; manual observations are recorded as manual.
