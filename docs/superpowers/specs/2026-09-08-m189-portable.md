# M189 — one portable file, and an import that starts nothing

Act VI of the v9 run (the plan's M193 and M194 rows). The 5.0 brief: *"Export names what is
included, what was scrubbed and what was omitted. Import previews the type and warnings, creates
a separate workspace, and keeps every executable thing inactive… Image pixels cannot be claimed
as automatically redacted: outward image inclusion is an explicit human review choice."*

## The file

`shared/portable.ts` is the format and both halves of it. A portable file is
`{ version, kind, createdAt, app, workspace: { name, panels }, templates, assets, omitted[],
redacted }` — and the parts it does NOT have are the milestone:

- **Built by TYPE, never by spread.** `buildPortable` assembles each panel field by field, the
  same structural trick `credential-store.ts`'s `list()` and the diagnostics bundle use: a
  terminal's resolved environment, a chat's transcript, a session id, a pid and a live cwd have
  NOWHERE to go in the record. A field added to a panel later cannot leak through a
  field-by-field build the way it would through a spread.
- **Scrubbed, and it says by how much.** Every string that travels passes `redactSecrets`, and
  the count is on the record and in the sentence the export reports. A file that was scrubbed
  silently would be a file a person trusts more than they should.
- **What was left out is named.** `omitted` carries one entry per thing that could not travel,
  with its reason: a watcher (it would arm on the other machine), a routine (it would fire), a
  review or a worktree (they name a repository the other machine does not have), a browser pane
  (it names a loopback port that is someone else's), a credential (there is none in the record
  by construction and the entry says so).
- **Pixels are a human choice.** Images are omitted by DEFAULT, with an `omitted` entry naming
  the count; `image-export` includes them as base64 only when the person asks. No claim is made
  that a picture was redacted — a picture cannot be scrubbed by `redactSecrets`, and saying
  otherwise would be the most dangerous sentence in this file.

## The import starts nothing

`parsePortable` has three answers: not a portable file at all, a version this app does not know
(with the version it found and the versions it knows), and a record with per-entry warnings.
Import creates a SEPARATE workspace — never merging into the one on screen — remaps every panel
and template id so nothing can collide with what is already here, and mints every panel in its
NOT-STARTED state: no PTY is spawned, no chat session is created, no watcher is armed and no
routine is scheduled. The check counts spawns across the import and requires zero.

## Doors

`export-canvas [path]` and `import-canvas [path]` ship as verbs, palette rows and a launcher
line; with no path the system's own file chooser is used, so this app invents no file browser.

## What this does not do

There is no extension registry and no example plugin (the plan's M195 and M196). A declarative
plugin loader is a new trust path into Electron, the filesystem and the credential store, and
the brief's own acceptance evidence for it is "installed from the documented external directory,
not from a special fixture-only registration" — which needs an external directory, an install
consent flow and a person to walk it. This run cannot prove any of that, so it is struck by name
in the ledger rather than shipped as a loader nobody has run from outside the repository.
