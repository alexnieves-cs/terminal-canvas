# Terminal Canvas 5.0 — v9 plan

Act 0, prepared on 2026-09-07 America/New_York from clean `main` at
`b8ca12861b1a4f8c81c93762356efb09e526a075`, version 4.1.0. The user’s
[finish prompt](2026-09-07-v9-finish-prompt.md) is the authority. Implementation waits for
`go`. This is a product plan, not a claim that any milestone below has shipped.

The result is one native workspace for arranging agents and their work. Orca supplies the
canvas shape; n8n supplies an editable graph and node library inside that canvas. The existing
conversation, terminal, watcher, template and broker paths remain the foundations. The
[5.0 brief](2026-09-07-v9-design-brief.md) governs every new or touched surface.

## Milestones and doors

C means a canvas gesture or a control on its object; P means a named palette row; W means a
workflow node executing the same operation; A means an agent-askable verb declared in
`src/shared/verb-table.ts` and connected to its executor. A declaration alone is not a door.
The table names the operations to cover. A necessary omission gets a named reason in the
ledger and a checkable entry in the four-door closure data before the milestone closes.

created. M200’s tag is local and is created only after the final merge and clean-tree check.

Each milestone gets its own spec and implementation plan before code. Read both load-bearing
files by module before editing. Delegate independent red-first check writing; record each
new check’s actual failing result before implementation, with scoped ids and guards that let
later checks run. A source edit gets the relevant suites and a fresh build before Electron
consumes it. Low-impact copy edits need visual review, not tests that repeat the copy.

milestone. Give them the diff, spec, plan, relevant repository rules and evidence paths, not
the author’s reasoning. The critic returns ranked findings including over-engineering and a
sentence per changed scene. The verifier runs commands and records exit codes. Resolve every
finding by name in the ledger. Electron commands are serialized across all agents; a verifier
owns the only Electron slot while running. No background staging, commits or merges race
against another agent’s edits. Stage exact paths.

Delegate the getting-started guide in M197 and the all-golden audit walk in M198 as independent

## Decisions at the seams

**Four doors need working transports.** The current verb table feeds the palette plan runner;
it does not itself expose those actions to an external agent. M180 establishes checked door
metadata and a bounded socket/`tc` bridge to the same validated executor. Keep URL requests
unable to run plans, refuse raw commands, cap operations and preserve confirmation and broker
identity rules. Each later verb must exercise this bridge, not merely add a table row.
Workflow execution for onboarding verbs is a temporary, named omission until M189 supplies
the canvas-action node adapter. Record the deadline in closure data and close it there; avoid
building a second workflow executor in Act I. Existing historical exclusions are reviewed
when their verbs are touched, rather than silently declared covered.

**Onboarding is a working canvas.** The main action starts an available conversation backend;
the existing M170 agent identity treatment is retained on agent terminals, and the chat
composer is the beginner’s input. Do not make a TUI mandatory to send the first message.
Readiness distinguishes binary discovery from authentication: found never means signed in.
Use one plain install/sign-in sentence and a vendor setup link where a person is needed,
then Check again; do not run installers or authenticate accounts in this development run.
Use existing backend capabilities, including their named refusals. A restored inactive
workspace is not a first run. Starter actions use ordinary mint paths and never auto-run
example commands or send seeded prompts. Keep the agent at working zoom; examples sit in
named nearby regions. M181 includes the minimal image-object foundation required by Act I;
M187 supplies its full ingestion and asset lifecycle. Later acts update the starter through
the same idempotent manifest, without overwriting a canvas a user has edited.

**One template, two editors.** Retire M133’s read-only projection limitation. Keep authored
coordinates and stable template/node keys; neither diagram layout nor array position invents
identity. A deliberate Edit on canvas binding projects one template draft into editable
objects. Both views apply the same validated operations to that draft, and Save writes the
same template with a revision check. A conflicting save keeps the draft and offers reload or
save a copy. Built-ins save as a user copy. Runs take an immutable definition snapshot and
retain their node mapping; later definition edits never rewrite historical outcomes. An
ordinary previously instantiated run is not silently enrolled as a live template editor.

M182–M184 must preserve terminal/chat fields that the old template shape did not
capture, including backend selection where applicable. Add only fields an actual editor or
runner consumes. The library and inspector derive from one closed schema registry, initially
for existing node kinds; Act V extends it. Persist configuration, not React state. Validate
edges before committing, retain the DAG/join rules, and make each complete gesture one undo.

**Preview discovery observes before it runs.** Prefer a port attributable to the selected
panel’s process tree; show a chooser for several answers. A package dev script is an offered
Start dev server action, never a process launched by discovery. Do not guess a live port
from a script name. Preserve an explicit URL. Resolve project roots in main and include the
file/toolbox path improvement from backlog #86 where that result is already available.
Project-change watching must see files with no open file panel, survive atomic replacements,
coalesce reloads and ignore dependency/build trees. Reuse M84’s lifecycle and file watcher
rules without starting `/usr/bin/true` for each reload. Keep the existing hardened webview,
the guest’s own URL authority and its panel-id lifetime. Width presets resize the guest
viewport inside the body; `.pf__body` is never transformed. Main captures the real guest with
`capturePage`, with a named unavailable arm when it cannot. No second page-script reader.

**Media objects use existing geometry.** Images, sticky notes, text and region frames are
sessionless panel variants with identity, rect, z, marks and history. They spend no terminal
WebGL slot and never enter the PTY registry. Preserve file-backed Markdown notes and existing
anchored ink. A frame owns a named region; group membership still owns ids and derives its
bounds. A frame does not become a second owner of child records or session lifetimes. Image
records reference bounded app-owned assets, not transient attachment files or outside paths;
undo must not point at bytes already collected. Missing assets keep an actionable object.
Retire unread pointer state from backlog #87 only while changing the relevant gesture seam.

**Workflow execution stays accountable.** A main-owned executor validates node schemas and
bounds response bytes, runtime and concurrency. It returns typed input/output/outcome data
for the inspector and the run. Shell uses the existing process runner; agent uses the
existing manager and its live limits. Transform starts as a documented set of JSON mapping,
selection and text-template operations, avoiding arbitrary JavaScript execution. HTTP uses
main’s bounded requester and never receives stored credentials for arbitrary destinations.
No redirect may carry a credential to a different host. Examples use fakes or loopback pages
in verification; external writes never run as part of this build.

GitHub uses the existing broker. Slack and email extend its closed service table and existing
credential schema deliberately; Resend’s HTTPS API is the initial email transport, avoiding
an SMTP dependency. Check current official API shapes when implementing these adapters.
The credential store keeps its three readers. A narrow node-run IPC may call the broker in
main; a generic renderer broker/credential-retrieval IPC remains prohibited. Every write,
including Test this node, requires an accountable workflow/agent identity and the existing
M102 approval path; no unscoped workflow call bypasses it. Approval answers and credential
entry remain human-owned exceptions to the four doors.

Cron uses the existing watcher/scheduler lifetime and a documented bounded five-field grammar
(minute granularity, displayed timezone), not a second scheduler. A fire-only watcher arm
can replace M133’s recorded no-op process. Missed triggers are reported, not replayed.
Webhook in is explicitly armed on loopback, with an unpredictable scoped route/authentication,
body/rate limits and teardown. It is usable by a local caller; public tunneling and hosting
are outside this local hand-distributed product. Relaunch/import does not silently re-arm it.

**Sharing copies authored work.** Use a single JSON envelope with an explicit version and
canvas/workflow discriminator, bounded embedded assets and existing record parsers. Absent,
malformed and unknown remain distinct; one malformed item costs that item where recovery is
safe. A future unknown envelope version is refused without creating a workspace. Remap
panels, groups, edges, anchors, template references and asset references together. Imported
work is dormant, with no credentials, live session identifiers, grants, running triggers,
automatic sends or hidden executable activation. Missing folders and plugins are named and
repairable. Preserve current text and PNG exports.

Apply M39 redaction recursively to outward text and metadata and report the count. Do not
serialize the entire layout store: accounts, settings and machine runtime are not shared
work. Regex redaction cannot inspect image pixels. Locally captured images stay local until
sharing is requested; portable exports omit image bytes by default and name the omission.
The human export surface can preview and explicitly include reviewed images. Agent-driven
outward export keeps those bytes omitted; record this door difference as a deliberate
limitation, not a claim of pixel redaction. Never send a screenshot merely to verify export.

**Extensions declare capabilities.** App extensions are separate from the Claude CLI plugin
inventory. A manifest under the app’s documented `userData/extensions/<id>/` directory may
declare namespaced node schemas mapped to bounded built-in operations and panel kinds rendered
by approved built-in surfaces. Loading a manifest executes no code. Validate versions, caps,
duplicate ids, path traversal and symlink containment. Missing/disabled extensions keep a
named inert placeholder. The external example demonstrates a useful HTTP-derived node and a
reading panel. Arbitrary main/renderer code, preload access, filesystem/network bypasses,
credential access, remote scripts and guest permission elevation are outside this surface.
Development copies live only in repository-local fixture userData; do not install into the
user’s actual profile. No marketplace or remote installation service is needed.

## Dependencies

No new dependency is expected. React, native HTML/SVG, Electron capture and Node’s built-in
filesystem/network/process facilities cover the planned work. Keep the existing icon and
token systems. No graph editor package, styling package, JavaScript evaluator, SMTP library,
archive library or hosted backend is planned. If measured implementation needs a small
package, add its exact purpose, alternatives and verification cost to this plan and the
ledger before installation. Any native module change requires `npm run verify:electron`.
