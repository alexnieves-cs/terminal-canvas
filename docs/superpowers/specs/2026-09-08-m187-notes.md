# M187 — notes, free text and named frames as equal objects

Act IV.2 of the v9 run (the plan's M188 row). The 5.0 brief: *"Sticky notes use readable UI
text and restrained theme tints. Free text is editable type with selection affordances rather
than a large empty terminal frame. A named frame defines a region with a quiet boundary; its
interior does not swallow another object's gesture."*

## The shape: one kind, three forms

A sticky note, a run of free text and a named region are the same record with a different
FORM: `{ kind: 'note', note: { form: 'sticky' | 'text' | 'frame', text, tint? } }`. Three panel
kinds would have meant three parsers, three partitions, three rail rows, three inspector arms
and three export paths for objects that differ only in how they paint — and the repo's own
`isTerminalPanel` exclusion list would have grown by three. One kind with a form is the same
decision M132 made for the workflow node kinds and M116 for the work card.

`form` decides the painting and nothing else:

- **sticky** — a tinted card, `--font-ui`, the text at reading size, one of four restrained
  theme tints (`--tint-yellow|blue|green|pink`, declared in BOTH theme blocks).
- **text** — the same text with no card at all: no fill, no border, no shadow. Editable type
  on the canvas, which is what the brief asks for and what a "large empty terminal frame" is
  not.
- **frame** — a named region: a quiet 1px boundary, the name at its top left, and NOTHING in
  the middle. Its body is `pointer-events: none`, so a click inside it reaches the object it
  encloses; the boundary and the name stay hittable so the frame itself can be selected,
  moved, renamed and deleted.

## Editing

The text is edited IN PLACE in a textarea inside the panel, committed on blur and on Escape,
with the canvas's keys stopped at the field (the memory node's and the address bar's shape).
It is the fifth text surface `docs/load-bearing.md` predicted, so it subscribes to
`edit:copy`/`edit:paste` and serves its own input — the shape `Palette.tsx` established. The
`edit:undo` half remains the documented, unfixed inheritance.

## Equal in every geometry rule, by construction

Selection, drag, resize, lock, pin, maximise, grouping, undo, persistence, the rail, the
inspector and export are `PanelFrame`'s and the panel array's, so this kind writes none of them
— the same argument M181's image kind made. `isNotePanel` joins `isTerminalPanel`'s exclusion
list (a note must never reach `assignTiers` with no spec), and semantic zoom shows the note's
own first line rather than a generic label.

## Doors

`note-add <form> [text]`, `note-set <panel> <text>` and `note-tint <panel> <tint>` ship as
verbs, palette rows and canvas gestures (the palette's forms, the node's own editor, the tint
chips on the sticky's chrome). The workflow door is the recorded omission every v9 verb carries
until M188's executor.

## What this does not do

A frame does not OWN what it encloses: it is a region drawn behind objects, not a group. Groups
(M35) already own membership, and a second ownership model would give every panel two possible
homes — the exact failure `shared/groups.ts` exists to avoid. A frame's interior not swallowing
a gesture is a DOM fact here; `hitTest`'s pure rect math still names the frame for a drop into
its interior, which is recorded rather than changed, because drop targeting is shared by six
callers and a form-aware exception belongs in its own milestone.
