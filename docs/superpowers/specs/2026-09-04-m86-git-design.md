# M86 — Git, deeply

**Status:** design, 2026-09-04. **Branch:** `m86-git`. **Kind:** feature + surface.
**Briefs built against:** 1.x principles 3 (identity leads), 7 (three states), 9 (a disabled
row names the fix); 2.0 principle 11 (the same fact in the same words everywhere).
**Thesis sentence:** what this canvas knows about a repository's branches — where each
worktree stands against the remote, and what every agent's worktree changed — read from git
alone, with no network ever touched.

## What this milestone is for

M37 gave every panel a worktree and M9 gave every panel a review. What the canvas cannot say
is the picture across them: which of the four agents' branches is ahead of the remote, which
is behind, and what all four changed at once. This milestone adds three facts and one node:
ahead/behind against the tracking branch; the branch picture across every worktree this app
created for one repository; a cross-worktree review, one node over N worktrees with each
worktree's diff a section; and the context pane's identity line naming the repository.

## Design

### The arguments and the parsers (`main/git-args.ts`, pure — `verify:review git.1`)

- `buildBranchArgs(root)` → `rev-parse --abbrev-ref HEAD`; `buildUpstreamArgs(root)` →
  `rev-parse --abbrev-ref --symbolic-full-name @{u}` (exits non-zero with no upstream);
  `buildAheadBehindArgs(root)` → `rev-list --left-right --count HEAD...@{u}`;
  `parseAheadBehind(stdout)` → `{ ahead, behind }` or null for anything but two integers.
- `buildWorktreeListArgs(root)` → `worktree list --porcelain`; `parseWorktreeList(stdout)` →
  `{ path, head, branch | null }[]`, a detached worktree carrying `branch: null`.
- `buildMergeBaseArgs(path, sha)` → `merge-base HEAD <sha>`, in the WORKTREE.
- **A fetch is never run.** Ahead/behind is what the local tracking ref says; the number can
  be stale by exactly as much as the user's last fetch, and the pane says `against the
  last fetch` beside it rather than pretending otherwise.

### The engine (`main/review-engine.ts`)

- `status(root)` → `{ kind: 'status'; branch; upstream: null | { name; ahead; behind } }`,
  or `git-missing` / `unreadable`. Three states in one answer: no upstream (null, a real
  answer), an upstream with counts, and git declining.
- `reviewAcross(root)` → one `section` per worktree this app created for `root` (the
  worktree records) plus the main tree first: `{ path; branch; label; panelId?; result:
  ReviewResult }`. A worktree's result is its diff since its FORK from the main tree —
  `merge-base HEAD <root's HEAD>` in that worktree — never a panel's baseline, which main
  drops when the panel is killed and which would make the node go blank exactly when a
  review of finished work matters. A worktree whose directory is gone is a section with
  `baseline-lost`, never a missing section.

### The wire

- `git:status(root)` and `review:across(root)` as invokes, in the contract and both diagrams.

### The surfaces

- **The context pane's Changes section** gains one line above the files: `main · ahead 2 ·
  behind 1 · against the last fetch`, or `main · no upstream`, or nothing but the existing
  note when git cannot answer. Three states.
- **The identity line names the repository**: a terminal panel inside a repository gets a
  `repository` field (the root's basename) at the top of its Detail fields — the small thing
  the scope decision names.
- **The branch picture**: the Workspaces pane's worktree rows (M37's list) gain the same
  ahead/behind phrase per row, read through `git:status` on each worktree's path.
- **The cross-worktree review node**: a review node whose subject carries `across: true`
  asks `review:across(repoRoot)` instead of `review:at`, and renders each section under a
  header naming the worktree's branch and label, the main tree first. Commit and discard are
  BLOCKED by name on it (`one worktree at a time — open that worktree's own review`): a
  commit across worktrees would be N commits pretending to be one. The palette gains
  `Review every worktree…`, enabled when the captured panel's repository has at least one
  worktree record and disabled with the count otherwise.

## What it must not break

- No network: `git-args.ts` must never build a `fetch`, `pull` or `ls-remote`; `verify:review
  git.1` asserts it by text.
- Every git call goes through `git-runner.ts`; nothing here shells out on its own.
- M37's worktree records and M9's review node keep their shapes; `across` is an optional
  flag that stays absent through every copy site.

## The failure modes this guards against, each with its check

| Failure | Check |
|---|---|
| `rev-list` output misparsed (`2\t1` vs `2 1`), or a missing upstream read as `0 0` | `verify:review git.1` |
| A detached worktree parsed as a branch named `HEAD` | `verify:review git.1` |
| A fetch built anywhere in `git-args.ts` | `verify:review git.1` |
| Ahead/behind wrong against a real remote after real commits | `verify:review git.2` |
| A section missing for a worktree whose panel was killed | `verify:review git.2` |
| The `across` flag coerced or lost through the layout | `verify:layout across.1` |
| A cross-worktree node rendering one flat list, or offering commit | `verify:panels across.1` |

## Amended after the verifier

- **`reviewAcross` answers for the REPOSITORY whatever tree was asked from**: a panel
  spawned into a worktree resolves its root to the worktree, and the first version found no
  records there and showed one section. `rev-parse --git-common-dir` names the main tree.
- **The identity line names the repository through `git:status`'s `repository`**, the
  common root — a worktree panel's leaf is `tc-<id>-<stamp>`, which names nothing.
- **The main tree's section is a plain tree diff**, never the `shared` attribution arm,
  which is about panels and has no meaning for the repository itself.
- **A record is checked against git's own worktree list** (this is what
  `parseWorktreeList` is for): a removed worktree and a branch with no common history are
  two sections with two different sentences, not one `could not be read`.
- **A merged branch reads `no changes`** — its fork is its own HEAD once merged, and the
  work is in the main tree; recorded as the rule rather than hidden.
- **The palette row keeps the ordinary review row's gate** (a file, a memory node or a
  never-started panel has nothing to review across), then the global worktree count; a
  per-repository count would need the target's root, which the palette does not hold.
- **Commit stays on the node, DISABLED with its reason**, beside the sentence in the body.
- **The branch picture is the palette's worktree rows** (M37's list) rather than a pane.
