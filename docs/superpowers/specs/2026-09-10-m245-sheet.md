# M245 — the `sheet` object (CSV first, xlsx through SheetJS)

## Why
A person and an agent both work in tabular files. Before this, a CSV on the canvas was a
text file: no cells, no formulas, no range copy. A sheet is a canvas object backed by a real
file, edited cell by cell, whose every write goes through main's compare-and-swap.

## Shape
**A sheet is a file panel with a view, not a new panel kind** — the checklist precedent
(M244). `FileSource.sheet?: SheetView` is the whole of what makes a file panel a sheet, so
selection, drag, tiering, undo geometry, export and the `isTerminalPanel` exclusion are
inherited rather than re-joined. `Canvas.tsx` renders `SheetNode` when `source.sheet` is
present.

`SheetView` persists only presentation and consent: `widths?` (per column, px),
`lossAccepted?` (the xlsx loss list the person confirmed). Cell content lives in the file and
nowhere else. Absent/malformed/unknown follows `parseChecklistView`.

## How CSV holds formulas (decided)
A cell whose text begins with `=` IS a formula and is stored in the file verbatim —
`=SUM(A1:A3)`, RFC 4180-quoted when it contains a comma, quote or newline. This is the
convention Excel, LibreOffice and Google Sheets all apply when they import a CSV, so a file
this app writes opens with the same formulas elsewhere. **Only formulas are stored; a computed
value is never written.**

- A literal text that begins with `=` is written with a leading apostrophe (`'=not a
  formula`), the spreadsheet convention; the apostrophe is display-stripped and edit-kept.
- Only this grammar evaluates: numbers, strings, refs (`A1`, `$A$1`), ranges, `+ - * / ^ &`,
  comparison is not in scope, parentheses, unary minus, and `SUM AVERAGE MIN MAX COUNT`.
  Anything else — `=HYPERLINK(…)`, `=cmd|' /C calc'!A0` — renders `#NAME?` and does nothing.
  That is this object's CSV-injection answer: it has no function that reaches outside the grid.
- Errors: `#REF!` (outside the grid, or a deleted row/column), `#NAME?`, `#DIV/0!`,
  `#VALUE!`, `#CYCLE!`.

## CSV fidelity
The parser remembers a BOM and the dominant line ending and the serializer writes them back,
so an edit to one cell changes only that cell's bytes on disk. Quoted fields, doubled quotes,
newlines inside quotes and ragged rows parse. A row shorter than the grid is written back at
its own length unless a cell past it was set.

## Reading and writing
- **Reads are bytes.** `file:read` and `file:write` gain an optional `encoding: 'base64'`. An
  ABSENT encoding is the utf8 path every existing caller takes, byte for byte. With base64 a
  read returns `{ kind: 'bytes', base64, bytes, mtimeMs }` — no line cap (a 2 MB CSV can have
  50,000 rows, and `FILE_MAX_LINES` exists to protect a text renderer this object does not
  use) — and the watcher arms with the same encoding so `file:changed` carries the same arm.
  No new channel.
- **Writes go through main's CAS** (`file:write`, `baseMtimeMs`), re-reading first, exactly as
  the checklist session does. There is no force door.
- **An external change** (another editor, an agent's Write tool) is reported by name —
  "data.csv changed on disk" — editing stops, and Reload adopts the disk. Nothing on disk is
  ever overwritten to resolve it.

## xlsx (Phase B)
SheetJS reads and writes. Only the first worksheet is edited. What SheetJS Community cannot
write back is **named**: charts, drawings/images, macros (VBA), pivot tables, comments, other
worksheets it will keep but not show, merged cells. The header carries a chip ("Drops on save:
1 chart, macros"); the first write asks once, and the confirmed list is kept in
`lossAccepted`. A list that grows later asks again.

**Dependency.** The npm-registry `xlsx` stops at 0.18.5, which carries CVE-2023-30533
(prototype pollution) and CVE-2024-22363 (ReDoS). A workbook is attacker-shaped input in the
ordinary case of "I opened a file from a repo I just cloned", so the dependency is SheetJS's
own tarball (`https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`) — same package, same
import name.

**Alias question**, settled by deleting and building (CLAUDE.md): recorded in the ledger.

## Grid
Virtualized: fixed row height, column prefix sums over `widths`, and only the visible window
plus overscan is in the DOM (`sheet-grid.ts`, pure). Column resize persists `widths`. Row and
column insert/delete shift formula references, and a reference into a deleted row becomes
`#REF!`.

## Keys
`Cmd+C/V/Z` are menu accelerators that reach the focused TERMINAL (CLAUDE.md). SheetNode
subscribes to `edit:copy`, `edit:paste`, `edit:undo`, `edit:redo` itself, acts only when
`[data-sheet-body]` holds focus, and `sheetFocused()` joins `shouldIgnoreKeys` so the canvas
clipboard and canvas undo stand down. Ranges travel as TSV — what every spreadsheet puts on
the clipboard.

## Header
`kindWord="sheet"`; `chrome` carries what the body does not: **rows × cols** and the
directory (`displayPath(...).short`), plus the xlsx loss chip. A sheet keeps its header under
the frame rule (M236): removing it hides the size and the location.

## Doors
`create-sheet` through `CREATABLE_OBJECTS` (pill row, palette, agent line, action node).
`sheet-edit <panel> <cell> <value…>`: canvas = type in a cell; palette `sheet.edit`; agent
`tc plan sheet-edit f1 B2 =SUM(B1:B1)`; action node with the same line. Refused to a
teammate's plan in M245 (M246 turns an agent's edit into a draft instead).

## Non-goals
Styling, number formats, multiple visible worksheets, sorting/filtering, comparison operators
and IF. Each is additive to the grammar or the view.
