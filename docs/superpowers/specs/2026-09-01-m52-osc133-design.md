# M52 — OSC 133 shell integration, and the run ledger

**Status:** designed 2026-09-02. Backlog #59 and #46, both reinstated by
the scope amendment (§7): "Main injects the prompt marks into the shell it
spawns; each command gets a marker, a gutter mark by exit status, and a
ledger row."

## What this milestone is for

Nothing in the byte stream is parsed for structure. If the spawned shell
emits OSC 133 prompt marks, each command becomes a first-class object: a
marker to jump to, a gutter mark green or red by exit status, and a row in
a ledger that turns "this panel exited with code 1" into "this panel has
failed the same command four times this afternoon". The shell is not a
vendor volunteering: main spawns it, so main can install the marks.

## Decisions

1. **Main injects, for the login shell only.** A panel whose `command` is
   ABSENT is a shell; main is the only party that knows which shell it
   resolved (`resolveCommand`), so injection is main's. zsh gets `ZDOTDIR`
   pointed at `userData/shell-integration/zsh`, whose `.zshenv`/`.zshrc`
   source the user's own (from the original `ZDOTDIR` or `$HOME`) and then
   add `precmd`/`preexec` hooks; bash gets `--rcfile` with a file that
   sources `~/.bashrc` and sets `PROMPT_COMMAND`/`DEBUG` hooks. Other shells
   get nothing and lose nothing. An agent CLI panel (`command` present) is
   not a prompt loop and is never decorated. Both backends: the direct one
   passes env and args straight through; tmux's `new-session` inherits the
   env it is given and runs the same argv.
2. **The marks are the standard four, plus the command text on C.**
   `A` prompt start, `B` prompt end, `C;<command>` command start (the
   command line, percent-encoded — the standard carries none, and the
   ledger needs it), `D;<exit>` command end. Written by the hooks, never by
   this app's own bytes.
3. **Main scans, on the scanner it already runs.** `agent-state.ts`'s
   escape-grammar state machine (`scanForBell`) gains OSC 133 recognition:
   a per-command EVENT at human speed from a scan that already runs on
   every chunk, chunk boundaries included. The scan never bumps
   `registry.version()` — the fifth entry to record that rule.
4. **The ledger is an append stream beside `layout.json`** (`runs.jsonl`,
   `main/run-ledger.ts`): panel id, command, cwd, started, ended, duration,
   exit code. One JSON line per command end, through its own writer (never
   `layout-store.ts`'s temp-and-rename — that pattern is wrong for a
   growing log), capped by line count with a ring trim, and `flushSync`
   stays the only thing `before-quit` waits on. It records NO output bytes,
   so it sits entirely outside #31's disclosure surface. It survives the
   direct backend, whose `exitCodeFor` is null by contract — the shell's
   `$?` on the mark is the exit code either way. `ledger:list(panelId)`
   returns a panel's recent rows, newest first.
5. **The renderer decorates from the same marks.** An xterm OSC handler
   registers a marker per `A` and, on `D`, a decoration on the command's
   marker: a gutter rib, `--ok` or `--fail`. Two palette rows on the focused
   terminal — *Previous prompt* / *Next prompt* — scroll to the marker
   before / after the viewport's top; *Copy last command's output* copies
   the lines between the last `C` and `D` marks. The handler creates
   markers and decorations only; it holds no text and bumps nothing.
6. **The context pane's Work tab lists the runs**: the last twenty rows for
   the selected panel, newest first, command · exit · duration, from
   `ledger:list`; hidden when there are none and the panel has no shell
   integration (a login shell with none is the same absence as an agent
   panel).

## What it must not break

- `verify:panels` 62/97 (amber by resolved value); the bell detector
  (`scanForBell`'s BEL detection is unchanged — an OSC 133 mark ends in BEL
  too, and must NOT ring the bell; the check for that is the point).
- The direct and tmux backends alike; no `tmux mouse`.

## Verification

- `verify:agent-state` `osc133.1`: the scanner yields `A`/`B`/`C`(command)
  /`D`(exit) events across a chunk boundary, and an OSC 133 mark's BEL is
  not a bell; `osc133.2`: a truncated mark at the end of a chunk completes
  on the next.
- `verify:tmux` `shell-integration.1`: the injection decides by resolved
  shell — zsh gets `ZDOTDIR`, bash gets `--rcfile`, an agent command gets
  nothing — and the generated rc sources the user's own before the hooks.
- `verify:file` `ledger.1`: append, list newest first, the cap trims the
  oldest, a malformed line costs that line.
- `verify:pty-manager` `osc133.1`: a real `/bin/zsh` spawned by the manager
  with injection emits the marks, and `true`/`false` produce ledger rows
  with exit 0 and 1.
- `verify:panels` `osc133.1`: a live shell panel shows a gutter mark per
  command with the right class; `Previous prompt` scrolls to the marker;
  the Work tab lists the runs.
- `verify:ipc` moves by one; `verify:meta` against both diagrams.
