# M52 — OSC 133 shell integration and the run ledger

**Status:** finished 2026-09-02.
**Branch:** `m52-osc133`. **Spec:** `docs/superpowers/specs/2026-09-01-m52-osc133-design.md`.
**Plan:** `docs/superpowers/plans/2026-09-01-m52-osc133.md`. Backlog #59 and #46.

One line: main decorates a login shell with OSC 133 at spawn and scans for the marks in the
byte path it already owns; the renderer paints them and navigates by them; a run ledger keeps
what each panel ran and how it ended, and never a byte of output.

## What landed

- `main/agent-state.ts`: `scanChunk(pos, chunk)` — one pass yields bells AND `133;A/B/C/D`
  marks, carrying an OSC accumulator across chunk boundaries; `scanForBell` is a wrapper.
  A mark's BEL terminator is consumed, not counted as a bell.
- `main/shell-integration.ts`: `shellIntegrationFor` — zsh via a `ZDOTDIR` shim that restores
  and sources the user's own files first, bash via `--rcfile`; an agent CLI is never decorated;
  absent `args` inject rather than throw.
- `main/run-ledger.ts` + `shared/run-ledger.ts`: append-only JSONL, per-file queue, count-tracked
  ring trim, malformed line skipped; `ledger:list` (contract, preload, handler, inert default).
- `PtyManager`: `RunsDeps` as the last constructor parameter (inert default), injection in
  `create()` for an absent `command`, `session.run` between `C` and `D`, a ledger row on `D`.
- Renderer: an xterm OSC 133 handler in `session-factory.ts` placing markers and `.cmd-mark`
  decorations coloured by exit; `jumpPrompt` / `lastCommandOutput` on `SessionHandle`;
  palette rows `Previous prompt`, `Next prompt`, `Copy last output`; the Work tab's runs list.
- Checks: `verify:agent-state osc133.1/.2`, `verify:tmux shell-integration.1/.2`,
  `verify:file ledger.1`, `verify:pty-manager osc133.1` (a real login zsh, rows
  `true`→0 and `false`→1), `verify:panels osc133.1/.2` (fault-injected by nulling the
  integration directory: both red, then restored).

## Snags

- The zsh hooks first emitted a literal `$__ec` because the mark was inside printf's
  single-quoted format; the payload is now a `%s` argument. `verify:pty-manager osc133.1`
  was the one that saw it.
- `verify:panels` hung twice with zero checks printed: first a TDZ (`runLedger` declared
  below the manager that held it), then `i.args is not iterable` on the seed create. Both
  threw inside the awaited seed BEFORE the watchdog is armed — the failure mode is a silent
  ten-minute stall, now recorded in `docs/load-bearing.md`.
- The panels checks were watched red AFTER green (fault injection), like M51's; recorded.

## Not proven

- Only zsh and bash are decorated; fish and others get no marks and no ledger rows, silently
  by design (the `shell: null` arm). A user's rc file that itself resets `ZDOTDIR` was not
  tried on a real machine.
