# Lens 3 — Adoption blockers

> An audit of everything between "an engineer hears about this" and "an engineer
> uses it on Tuesday for the third week running." Written against `2.3.0`
> (`package.json:3`), on branch `m117-engines`, at `98aaf35`.
>
> **The headline finding is not a feature gap and not a quality gap.** This
> repository is, by the standards of a personal project, exceptionally well
> engineered: 60,335 lines of TypeScript, ~1,700 assertions across 33 verify
> suites, a 3,974-line load-bearing-invariants document, an honest SECURITY.md,
> issue templates, a CI workflow, an MIT licence, and a codebase whose comments
> explain *why* rather than *what*. None of that is currently reachable by
> anybody. **The GitHub repository is private and has zero releases**, so the
> download link in the README is a 404 for every human being on earth except its
> author. Every other item in this document is downstream of that one.

---

## Method and ranking rule

Ranked strictly by **(how many prospective users the blocker eliminates) ×
(how cheap it is to fix)** — highest ratio first. That deliberately puts a
one-line change that unblocks everybody above a structurally correct but
expensive port.

Two labels are used throughout:

- **Blocker** — the user cannot proceed. Adoption stops here.
- **Friction** — the user can proceed, but a measurable fraction won't bother.

---

# The ranked list

## 1. The repository is private and has published zero releases — the README's download link 404s

**What it is.** `README.md:199` tells a stranger to "Grab the `.dmg` from
[Releases](https://github.com/alexnieves-cs/terminal-canvas/releases)". That
page does not exist for them:

```
$ gh repo view --json visibility,isPrivate,stargazerCount
{"isPrivate":true,"visibility":"PRIVATE","stargazerCount":0}

$ gh release list
(empty)
```

There is no release workflow either — `.github/workflows/` contains exactly one
file, `verify.yml`, which runs `npm run verify` on push/PR
(`.github/workflows/verify.yml:16-66`). Nothing in the repo ever publishes an
artifact.

The artifacts that *do* exist are on the author's disk only, and are stale:

```
release/Terminal Canvas-1.0.0-arm64.dmg
release/Terminal Canvas-1.1.0-arm64.dmg
release/Terminal Canvas-2.0.0-arm64.dmg     # newest, three versions behind
```

...and `release/` is gitignored (`.gitignore:4`). There is no `2.3.0` build
anywhere, signed or not. There is no download page, no website
(`gh repo view` → `homepageUrl: ""`), and no Homebrew cask (no `Casks/`,
no `brew` reference outside `brew install tmux` in the prerequisites).

**Who it eliminates.** Everyone. 100%. This is not a figure of speech.

**Cost to fix.** Minutes to hours. Flip the repo to public; run
`npm run package`; `gh release create v2.3.0 release/*.dmg`. A publishing
GitHub Action is another hour.

**Verdict: true blocker, and the single highest-ratio item in this document by
an enormous margin.** Everything below is only worth doing after this.

## 2. A canvas application with no picture of the canvas

**What it is.** `README.md` is 981 lines and contains **zero screenshots**. Its
only images are three shields.io badges (`README.md:3-5`). The tracked image
files in the entire repository are `build/icon.png`, `dirs.png`, and a Playwright
scratch copy — none of them show the product.

This is especially painful because *the pictures already exist and are already
generated by a maintained harness*. `npm run shot` renders 39 PNGs of the real
renderer into `out/shots/` (`package.json:33`, `scripts/shot.cjs`) — `board.png`,
`overview.png`, `kinds.png`, `chat.png`, `browser.png`, `attention.png`, and
more. `README.md:146-179` ("What it looks like") **describes six of them in
prose** rather than showing them. `out/` is gitignored (`.gitignore:2`), so they
never leave the author's machine.

**Who it eliminates.** Most of the people who survive item 1. A spatial-canvas
product is sold by a picture; a wall of prose describing a picture is not a
substitute. For a GIF-driven category (Figma-for-terminals), the top of the
funnel is visual or it does not exist.

**Cost to fix.** An hour. Commit six of the existing PNGs to `docs/img/` and
inline them at `README.md:146`. A 20-second screen recording of a dispatch →
worktree → PR flow would be worth more than the next five items combined, and
costs an afternoon.

**Verdict: friction, but decisive friction.** Highest ratio after item 1.

## 3. Apple Silicon only — Intel Macs get nothing, and the fix is one argument

**What it is.** `build/builder-config.cjs:27` reads
`const arch = (opts && opts.arch) || 'arm64'`, and the entry point calls it with
no arguments: `electron-builder.config.cjs:6` is
`module.exports = buildConfig()`. So every build is `arm64` and only `arm64`
(`build/builder-config.cjs:90-93`). `README.md:11` states this ("macOS only,
Apple Silicon by default").

The architecture is *already* a parameter, and there is already a check pinning
that it can be widened — `scripts/verify-package.cjs:112-118` asserts
`buildConfig({ arch: 'universal' })` produces universal targets. The capability
is built; it is simply not called.

**Who it eliminates.** Every Intel Mac user, silently — the `.dmg` will not
launch. That is a meaningful, though shrinking, slice of working engineers
(older corporate fleets in particular).

**Cost to fix.** One line: `buildConfig({ arch: 'universal' })`. Then widen
`scripts/verify-package.cjs:103-108` (which currently asserts every arch is
`arm64`) and accept a ~2× artifact size (the current `.dmg` is already 134 MB).

**Verdict: true blocker for that population, near-zero cost.** Very high ratio.

## 4. Unsigned and un-notarized — current macOS says the app is "damaged"

**What it is.** `build/builder-config.cjs:101` sets `identity: null`,
deliberately and with a good comment (`:95-100`): explicit null makes the build
hermetic rather than picking up whichever keychain identity the build machine
has. There is no notarization step anywhere, and `README.md:202-217` and
`SECURITY.md:75-90` both document the consequence honestly.

**What a stranger actually sees on current macOS.** A downloaded, quarantined,
unsigned, un-notarized `.app` on macOS 15/26 does **not** get the friendly
"unidentified developer" dialog with an Open button. Gatekeeper's assessment of
an ad-hoc/unsigned bundle that failed notarization surfaces as
**"Terminal Canvas is damaged and can't be opened. You should move it to the
Trash."** — which reads to a normal person as a corrupt download, not a policy
decision. The macOS 15+ recovery path is: open the app once (get the block),
then **System Settings → Privacy & Security → "Open Anyway"**. The
right-click → Open bypass that most blog posts still recommend was removed in
Sequoia. The README does get this right at `:207-209` (it names System Settings
first and marks right-click as "macOS 14 and earlier") and offers
`xattr -dr com.apple.quarantine` at `:213`.

There is a real second-order cost documented at `SECURITY.md:80-90`: on macOS,
`safeStorage`'s protection is a Keychain ACL bound to the app's **code
identity**. An unsigned binary has no stable designated requirement, so
"encrypted at rest" for the user's GitHub/Jira tokens "may amount to little more
than obfuscation." The project states this itself, which is admirable, and it is
also a sentence that ends the conversation at any company with a security review.

**Who it eliminates.** Nearly every user inside a company with MDM or a security
policy — those machines will refuse or flag it outright. Among individuals, the
"damaged" wording eliminates a large fraction who assume a bad download. A
motivated engineer who reads the README gets through fine.

**Cost to fix.** $99/year Apple Developer Program, plus notarization wiring
(`electron-builder` supports `notarize: true` with an API key; roughly a day
including CI secrets). This is the only item in the list whose primary cost is
**money and identity, not engineering**.

**Verdict: true blocker for corporate adoption, high friction for everyone else.**
Ranked here rather than higher only because it is the one item that cannot be
fixed for free.

## 5. There is no update path of any kind

**What it is.** Nothing. A repo-wide grep for
`electron-updater|autoUpdater|checkForUpdates` across `src/`, `scripts/`,
`docs/`, `build/`, `.github/`, `package.json` returns **zero matches**.
`package.json` dependencies are exactly `@sentry/electron` and `node-pty`.

The one artifact that looks like update infrastructure is
`release/latest-mac.yml` — but that is a byproduct electron-builder emits
unconditionally, it is gitignored, it is stale (it names `2.0.0`), and nothing
reads it.

**The actual consequence.** A user who installs 2.3.0 has *no mechanism whatsoever*
to learn that 3.0 exists. There is no in-app notice, no version check, no
mailing list, no release feed they were pointed at, and — per item 1 — no
Releases page to watch. They will use 2.3.0 until it breaks against a `claude`
CLI protocol change, and then they will delete it. Given that this app's core
value depends on parsing *other vendors'* CLI stream formats
(`shared/transcript.ts` measured against claude 2.1.259,
`shared/codex-transcript.ts`, `shared/acp-transcript.ts`, copilot 1.0.83 per
`README.md:910`), a stale install is not merely un-improved — it is on a clock.

**Who it eliminates.** Nobody at install time; ~everybody at the three-week
retention mark, which is the exact bar this audit was asked to measure.

**Cost to fix.** Two tiers. Cheap tier (hours): a startup fetch of the GitHub
releases API and a dismissible "3.0 is out" notice. This works unsigned. Full
tier (days, and **gated on item 4**): `electron-updater` — Squirrel.Mac requires
a signed bundle, so real auto-update cannot ship before code signing does.

**Verdict: true blocker for retention, not for install.** The cheap tier should
ship with the first public release.

## 6. A fresh install has no spend ceiling and no concurrency ceiling

**What it is.** Both of M82's ceilings default to *off*:

- `src/shared/settings-schema.ts:150-158` — `agents.maxConcurrent`, `default: 0`
- `src/shared/settings-schema.ts:160-169` — `agents.budgetUsd`, `default: 0`

and `0` means no ceiling, enforced as `if (limits.budgetUsd > 0 …)` /
`if (limits.maxConcurrent > 0 …)` at `src/main/agent-session.ts:286,292`. The
schema comment states it plainly (`settings-schema.ts:147-148`): *"0 is no
ceiling for both, which is every canvas that has never opened this page."*

Nothing in the first-run path mentions either. The Launcher
(`src/renderer/canvas/Launcher.tsx:70-141`) names presets, chat doors, a file
door and the environment report — no budget.

Note the sharp asymmetry with the *other* safety default, which is exemplary:
teammate `places` default to `[]`, and `src/shared/places.ts:14-15` documents
that "no places is NO filesystem, never everything" (`insidePlace` returns
`false` on an empty list, `:42`). So filesystem authority is deny-by-default and
**spend is allow-by-default**. Meanwhile M97's `auto` modes
(`src/shared/auto.ts`) exist precisely to run an agent unattended for many turns.

**Who it eliminates.** Nobody at install. It eliminates them *after* the first
surprise invoice, and it is the single fact most likely to turn an enthusiastic
early user into a public complaint. It also makes the app unrecommendable inside
a company.

**Cost to fix.** Very low. Either ship a non-zero default (e.g. `budgetUsd: 10`,
`maxConcurrent: 4`) or add one line to the Launcher and a first-run prompt. The
entire enforcement mechanism is already built, tested, and shipping — only the
default is wrong.

**Verdict: friction that behaves like a blocker.** Best ratio of anything in the
code.

## 7. Discovery explains itself — but not for `copilot`, and not when the shell times out

The M107 claim (`CLAUDE.md:513-517`) is **substantially true and better than
most shipping products.** It holds where it matters:

- Three states, not two: `src/shared/env-report.ts:30-52`. The `no-answer` arm
  (`:47-49`) carries the fix verbatim — *"a slow or prompting ~/.zshrc; put PATH
  edits in ~/.zprofile, then Check again"* — and is never rendered as
  "not installed."
- It is **on the first screen**, not buried: the outcome sentence renders on the
  Launcher itself (`src/renderer/canvas/Launcher.tsx:129-141`) with a
  `Check again` button wired to a real re-probe
  (`src/main/shell-env.ts:107-113`).
- A second banner fires when the shell probe failed
  (`src/renderer/canvas/Canvas.tsx:5089-5093`).
- The full report is a palette row **visible at rest**
  (`src/renderer/palette/commands.ts:2192-2205`), subtitled `N of 3 CLIs found`.
- The broader "no dead ends" convention genuinely holds across credentials
  (`src/shared/credential-schema.ts:38-40`), integrations
  (`src/renderer/shell/integration-model.ts:56-67`), the vault
  (`VaultPane.tsx:79-105`), teammates, routines and work items.

**Three places it does not hold:**

**(a) `copilot` is invisible to the environment report.**
`REPORTED_CLIS = ['claude', 'codex', 'git']` (`src/shared/env-report.ts:8`), but
`copilot` is probed at startup (`src/main/index.ts:867`) and gates *two*
backends (plain headless and ACP — `src/shared/agent-backends.ts:177,210`). A
user missing `copilot` reads **"3 of 3 CLIs found"** while the copilot and ACP
doors are dead. Cost to fix: one array element plus an `INSTALL` entry.

**(b) A timed-out shell is reported to the user as "not installed."** This is the
sharpest one, because it reintroduces the exact failure `env-report.ts:38-39`
says it exists to prevent. When the probe fails, `loginEnv` falls back to
launchd's bare PATH (`src/main/shell-env.ts:142`); `resolveAvailability`
(`src/main/presets.ts:224-239`) is driven by that PATH; so the Launcher renders
**"Start Claude… — not found on PATH — install the Claude Code CLI"**
(`Launcher.tsx:105`) *directly above* an env line correctly saying the shell
never answered. Same for the chat door
(`src/shared/agent-backends.ts:115`) and `agent:create`
(`src/main/index.ts:1321`). The user is told to reinstall a CLI they already
have. Cost to fix: thread `probeOutcome`'s `no-answer` state into the
availability reason — a few sites, low risk.

**(c) Install hints are prose, not commands.**
`src/renderer/canvas/Launcher.tsx:50-53` is the whole map:

```js
const INSTALL = {
  claude: 'install the Claude Code CLI so `claude` is on your PATH',
  codex:  'install the Codex CLI so `codex` is on your PATH'
}
```

Two entries (no `copilot`), and neither is copy-pasteable. A new user who has
never installed `claude` is told *that* they should, not *how*. Cost to fix:
trivial — put the real `npm i -g` / `brew install` line in the string.

**Two more silent-failure notes:** the env-report invoke is swallowed with a
bare `.catch(() => {})` at `Canvas.tsx:2786`, which makes the env line, the
banner and `Check again` all vanish together; and tmux degradation is a
`console.warn` (`src/main/tmux-probe.ts:161-165`) — a first-run user who loses
their agents to `⌘R` was never warned in the UI.

**Who this eliminates.** A modest but real fraction — specifically the users
whose dotfiles are slow or interactive, which correlates with *experienced*
engineers who have elaborate shell setups. Exactly the target audience.

**Cost to fix.** Low across all five sub-items. **Verdict: friction.**

## 8. `npm run verify` cannot run on Linux or Windows — contributors are locked out too

**What it is.** Seven `package.json` scripts hardcode the macOS Electron bundle
path: `:33` (`shot`), `:34` (`verify:pty`), `:35` (`verify:pty-manager`), `:36`
(`verify:window`), `:37` (`verify:ipc`), `:59` (`verify:canvas`), `:60`
(`verify:xterm`), `:61` (`verify:panels`) — all
`node_modules/electron/dist/Electron.app/Contents/MacOS/Electron`. Six are in
the aggregate `verify` chain (`package.json:62`). On Linux the binary is
`node_modules/electron/dist/electron`.

Since `CONTRIBUTING.md:9-16` declares `npm run verify` to be "the entire gate,"
a contributor on Linux cannot satisfy the project's one stated requirement — not
because the app is macOS-only, but because of a path literal.

**Cost to fix.** One line each: `require('electron')` returns the binary path on
every platform. **Verdict: blocker for contributors, trivially cheap.**

## 9. macOS-only — Linux is bounded work, Windows is four rewrites

This is a **declared constraint**, not drift (`README.md:11,187`;
`CLAUDE.md:21`; `.github/workflows/verify.yml:2-6`). It matters here only
because the brief asks about "every software engineer," and roughly half of them
are not on a Mac.

The codebase is in better shape than expected: only **two** `process.platform`
branches exist in the entire app (`src/main/index.ts:1802`, the correct
`window-all-closed` idiom; and `src/preload/index.ts:334`, which exposes
`platform` over the bridge — and **nothing in the renderer reads it**, so the
one adaptation hook is dead code today). File reveal and link opening already
use the portable `shell.showItemInFolder` / `shell.openExternal`
(`src/main/index.ts:1618,1667`); the dock badge is already optional-chained
(`:312`). There is no `pbcopy`, no `open -R`, no `sips` in `src/`.

**Linux — moderate and bounded, nothing architecturally blocked:**

| Area | Evidence | Work |
|---|---|---|
| node-pty, tmux, `ps` parsing | `machine-cost.ts:12` already says "macOS and Linux" | **none** |
| Control socket server | `control-server.ts:70-77` (POSIX socket + chmod) | none; but `tc`'s default paths are mac literals (`src/cli/tc.ts:52-53`) — small |
| Shell fallback | `shell-env.ts:122` `'/bin/zsh'` | trivial |
| `safeStorage` | `credential-crypto.ts:18`, refusal at `credential-store.ts:143-146` | **real** — no keyring ⇒ credentials permanently refused |
| URL scheme | `index.ts:710` `open-url` is macOS-only; `second-instance` (`:1755`) ignores argv | medium |
| Menu / titlebar | `menu.ts:42-84`; `index.ts:724` `hiddenInset` | small |
| Packaging | `builder-config.cjs:86-102` has only a `mac:` block | medium |
| **Keyboard** | ~10 hooks are `metaKey`-only — `useKeyboardNav.ts:55`, `usePalette.ts:145`, `useViewport.ts:395`, `useNavGrid.ts:72,142` (a `key === 'Meta'` state machine), `FileNode.tsx:721`, `session-factory.ts:93`, others | **broadest single change**; mechanical, but touches every renderer suite |

**Windows — structural, four separate rewrites plus a lost feature class:**
the control socket must become a named pipe and loses its 0600 property
(`control-server.ts:70,77`); OSC-133 shell integration is pure zsh/bash +
`od`/`tr`/`sed` (`shell-integration.ts:45-62`); `machine-cost.ts:96` has no `ps`;
and `shell-env.ts:172` splits `PATH` on `':'`, which is broken outright on
Windows and silently takes `whichFromEnv`, `tmux-probe` and the CLI report with
it. `tmux` does not exist, so session persistence and `session.keepOnQuit`
vanish as a category. Two latent bugs also surface: `link-open.ts:38-48` would
read `C:\foo` as a URL scheme, and `menu.ts:131` binds `CmdOrCtrl+C` — which on
Windows/Linux would swallow SIGINT, the single most important key in a terminal.

**Who it eliminates.** Every non-Mac engineer. **Cost.** Linux: weeks. Windows:
a quarter, honestly. **Verdict: true blocker for that population; correctly
deferred.** Low ratio — listed for completeness, not as a recommendation.

## 10. The existing-setup wall — nothing you already have comes with you

The brief's "I already have a setup" wall is real and largely unaddressed.

**Prior conversations: no.** `Open as chat` exists and works well, but only for
sessions *this app started*. `importSession` (`src/main/index.ts:1416-1428`)
opens with `layoutStore.session(fromPanelId)` and refuses with *"that terminal
was not started as a claude session"* (`:1418`) when absent. The underlying
reader is fully capable of the general case — `claude-transcript-import.ts:5-8`
parses `~/.claude/projects/<slug>/<uuid>.jsonl`, another program's format,
measured and handled carefully — but there is **no door that lets a user browse
their existing Claude Code history and open one on the canvas.** For a user with
six months of `claude` transcripts, that is the difference between "a new tool"
and "a new view onto my work."

**Existing worktrees: no.** `worktree-manager.ts` only ever *creates*
(`tc/<panelId>-<stamp>` under `userData/worktrees`,
`src/main/index.ts:369-378`); there is no adopt/discover path for the worktrees a
user already has.

**Existing tmux sessions: no.** The backend attaches to sessions it named. There
is orphan *recovery* (`session:recover`) for this app's own sessions, not
adoption of yours.

**Project config: partial, and it's the best thing here.**
`src/main/prompts.ts` reads `.claude/commands/*.md` from a panel's cwd, in Claude
Code's own format, so prompts version-control with the project
(`README.md:174-177`). This is exactly the right instinct — and it is the *only*
project-local file the app reads.

**Cost to fix.** The transcript browser is the high-value one and is mostly UI:
the parser, the glob and the refusal arms all exist. Days, not weeks.
**Verdict: friction at install, blocker for "why would I switch."**

## 11. No sharing story at all — this is a single-player application

**What exists.** `export:panel-text` (a panel's log, ANSI-stripped, secrets
scrubbed) and `export:canvas-png` (`src/main/ipc.ts:443-444`). That is the
entire outbound surface, and `README.md:191-193` says so honestly: the app
cannot "export a canvas another instance can open."

**Where everything lives.** All under `app.getPath('userData')` —
`layout.json` (`index.ts:142`), `layout-snapshots/` (`:140`), `scrollback/`
(`:366`), `worktrees/` (`:378`), `memory/` and `memory/teammates/`
(`:539,545`), `broker-audit.jsonl` (`:625`), `sandbox/` (`:1328`),
`credentials.json`. **Not one of these is a file a user could commit to a
repository or hand to a colleague.**

**What cannot be shared, though it obviously should be.** Templates
(`src/shared/templates.ts` — "a shape of work": nodes, edges, `{{parameters}}`),
lineups (`src/shared/lineups.ts`), routines, teammates, presets. These are
*exactly* the artifacts a team would want in-repo — "here is our
review-and-fix template, checked in beside the code." They are all top-level
keys in one machine-local `layout.json`. There is no import door either: the only
`showOpenDialog` calls are `openFile` for file panels (`src/main/ipc.ts:638-639`)
and `openDirectory` for teammate places (`src/main/index.ts:1591`).

Two further facts sharpen this. **Lineups are not user data at all** —
`src/shared/lineups.ts:34` is a closed constant of four ids
(`solo`/`pair`/`workbench`/`swarm`), not saved, not editable, not shareable. And
**routines cannot outlive the process**: `src/shared/routines.ts:11-13` states
"In-app only… the app is not a daemon", a tick that falls while the app is
closed is recorded `missed` and never fired, and `ROUTINE_LIMIT_WORD` (`:40`)
says so to the user — so there is no team-level or unattended automation story
either.

Even `layout.json` could not simply be committed: it holds absolute
machine-specific paths (per-panel `cwd`, absolute `places[]` and `skills[]`,
worktree paths) alongside panel ids, and there is no import path to read it back.

There is no multi-user, remote or shared-state concept anywhere — confirmed by
grep across `src/`. The single-instance lock means a losing instance touches no
store, socket or PTY (`src/main/index.ts:857-863`); the control server is
Unix-domain only with no `port` and no way to add one without changing its one
`listen` call (`src/main/control-server.ts:13-14`). (An accounts design exists as
unstarted backlog item #28, `docs/ideas-backlog.md:974`.)

Worth crediting: the one project-local surface is *inbound and read-only*, and
deliberately so. `src/main/prompts.ts:9-14` — "A prompt in the user's repository
belongs to the repository — it version-controls with the project and works when
they are in a plain terminal outside this app… **Writing it is deliberately out
of scope: authoring a file someone will commit is a decision to ask for, not to
acquire as a side effect of 'save'.**" That is the right instinct, and an
export/import story should inherit it rather than contradict it.

**Who it eliminates.** Every team evaluation. The path from "one engineer likes
it" to "our team uses it" does not exist, and team adoption is where tools like
this actually survive.

**Cost to fix.** A `.tcworkspace.json` — export/import for templates and
lineups, read from the repo root — is a well-scoped week and would be the
highest-leverage *feature* on this list. The record schemas are already parsed
with strict absent/malformed/unknown discipline, so the format work is mostly
done.

**Verdict: blocker for team adoption; friction for individuals.**

## 12. Trust posture: genuinely strong writing, two real gaps

**What a security-conscious engineer would find, and it is better than most.**

- `SECURITY.md` is 90 lines and unusually honest. It states the app spawns
  arbitrary local commands as the product (`:10-16`), that panel processes
  outlive the window (`:21-23`), that committing from a review node runs your
  pre-commit hooks (`:24-30`), that `credential:verify` is "the app's first and
  only outbound network call" (`:51-56`), and — remarkably — that
  `safeStorage` on an unsigned build "may amount to little more than
  obfuscation" (`:80-90`). Very few projects volunteer their own weakest claim.
- **No `credential:get` exists, by construction** — plaintext crosses no IPC
  boundary in either direction (`CLAUDE.md` architecture notes; readers pinned to
  exactly three files by `verify:meta readers.1`).
- **Deny-by-default filesystem authority.** `src/shared/places.ts:1-50` decides
  on the *real* normalised path with an injected `realpath`; `..` out, a symlink
  out, and a relative path are each refused and each a check
  (`verify:teammates places.1–.3`); empty list ⇒ nothing (`:42`).
  The honest limit is stated: the gate bounds what *the app* does for a
  teammate — **the CLI's own tool calls are the CLI's permission system's.**
- **Electron hardening is measured, not asserted.** `verify:electron` runs
  Electronegativity over `src/` pinned to the installed Electron version, with a
  closed seven-row `ACCEPTED` list (`scripts/verify-electron.cjs:48-63`) where a
  *new* finding fails **and a row that stopped firing also fails**. Each accepted
  row carries a `why`: CSP (xterm sets inline styles; `script-src` stays
  `'self'`), `sandbox: false` (the preload needs `require('electron')`), the
  preload path, auxclick, two `openExternal` doors, and the `tc://` protocol
  client. The `<webview>` guest is hardened by name in `main/index.ts` and pinned
  as text by `verify:meta browser.1`.
- **Telemetry is off and bring-your-own.** `src/main/telemetry.ts:30-36`:
  `telemetryPlan` is `no-dsn` unless the user pastes their *own* Sentry DSN
  (`settings-schema.ts:415-425`, default `''`), with a separate `malformed-dsn`
  arm so a typo never reads as "off". `scrubEvent` builds events from an
  **allowlist**, dropping breadcrumbs, `request`, `user`, `extra`, `tags`,
  `contexts.device` and frame `vars`, and replaces `<home>`/`<userData>` in every
  kept string. **Nothing is sent to the author, ever.** For a corporate reviewer
  this is close to ideal.

**Gap A — the security document contains a claim that is no longer true.**
`SECURITY.md:53-56` states that `credential:verify` "is the app's **first and
only outbound network call**." M112 added `@sentry/electron` as a *runtime*
dependency (`package.json:68`), and the broker (M87) reaches `api.github.com`
and a Jira site. `SECURITY.md` contains zero occurrences of "telemetry",
"Sentry", or "crash report". This is the one sentence in the file a security
reviewer will check, and it is wrong — which retroactively devalues the many
sentences that are right.

**Gap B — `SECURITY.md` is not linked from `README.md` or `CONTRIBUTING.md`.**
A reader of the 981-line README is never pointed at the 90-line document that
answers their actual question. Cost: one link.

**Gap C — the `terminal-canvas://` URL door is undocumented and unprompted.**
`app.setAsDefaultProtocolClient(CONTROL_SCHEME)` registers the scheme when
packaged (`src/main/index.ts:1744`). The door is properly narrow — `parseControlUrl`
(`src/main/control-protocol.ts:177-189`) requires `parsed.host === 'open'` and
refuses every other verb, `command`/`args` are refused at the shared parser
(`:61-63`), an unknown preset and a non-existent `cwd` are both refused
(`:201-219`). But **any web page can fire
`terminal-canvas://open?preset=<name>&cwd=<path>` with no confirmation dialog
and no origin check**, spawning one of the user's own presets in a chosen
existing directory, repeatedly. That is not RCE, and the design is defensible —
but it is exactly the question a reviewer asks, and `SECURITY.md` does not
mention the URL scheme at all.

**Gap D — the places caveat lives only in `CLAUDE.md`.**
`CLAUDE.md:455-456`: *"The gate bounds what the app does for a teammate; the
CLI's own tool calls are the CLI's permission system's."* This is the single
most likely thing a stranger will misunderstand about teammate scoping — "I
scoped this agent to one folder" is *not* what the gate provides — and it
appears in neither `SECURITY.md` nor `README.md`.

**Gap E — telemetry is undocumented where anyone will look.** The
implementation is exemplary (see above), but `Sentry` appears in `README.md`
exactly once, buried in the M112 milestone-table row (`README.md:904`). There is
no Privacy or Telemetry section anywhere. Two things a corporate reviewer needs
and cannot find: that there is **no vendor DSN** and data goes to a project the
*user* owns; and that the SDK **ships in every packaged build regardless**,
because electron-builder resolves runtime deps from `package.json`
(`docs/load-bearing.md:2157-2160`) — bytes and attack surface in the installer,
not traffic. The path has also never been exercised against a live Sentry
project (`docs/load-bearing.md:3954-3958`), and the one prior bug in this area
was silent (the CSP swallowing the `sentry-ipc://` fallback with no error).

**Gap F — a broker write with no teammate attached never asks for approval.**
`src/main/broker.ts:229` gates the approval prompt on
`req.teammateId !== undefined`. But `teammateId` is only populated when the
asking panel *is* a teammate chat:
`src/main/control-handler.ts:109` —
`const teammateId = panelId === undefined ? undefined : deps.teammateOf?.(panelId)`.
So an ordinary agent panel running
`tc api github DELETE /repos/you/thing` reaches
`deps.fetcher` with **no card, no prompt, and the user's real token**. It is
audited (`broker-audit.jsonl`) but not authorized. M102's design intent is
right; the default case falls through it. Cost to fix: low — make the
no-teammate write path ask too, or refuse it.

**Gap G — none of it is findable by the person who needs it.** All of the above
lives in `SECURITY.md` and a 3,974-line `docs/load-bearing.md` inside a
**private** repo. The security posture is the strongest argument this project
has for corporate adoption, and today it is unreadable by any corporate
reviewer.

One more note in the project's favour, since it bears on trust: the broker's
audit is genuinely user-visible — `broker:audit`
(`src/shared/ipc-contract.ts:387`, handler `src/main/ipc.ts:619`) renders rows in
`IntegrationsPane.tsx:87-100`, every call *including every refusal* is one row
(`broker.ts:185-196`), metadata only, ring-trimmed at 2000 lines. The honest
limit is that an audit write failure is swallowed by design
(`broker-audit.ts:42` — "an audit that cannot be written must not stop the
call"), so it is best-effort rather than a hard control; and `cost` on a spend
card is unverified caller text (`control-protocol.ts:143`), a display value, not
an enforced budget. There is no spend ceiling on the broker beyond
`BROKER_IN_FLIGHT_MAX = 8`.

**Verdict: the posture is a selling point being wasted — and it has drifted.**
Gap A (a false claim) and Gap F (a real approval hole) want code and prose
changes; C, D and E are missing paragraphs; B is a hyperlink; G is item 1 again.
Fixing A–E is perhaps a day and turns `SECURITY.md` from a liability back into
the asset it nearly is.

## 13. Performance and scale — honest, documented, and lower than users will expect

**The real ceiling is eight.** `src/renderer/canvas/lod.ts:17` —
`export const LIVE_BUDGET = 8`, commented "Browsers drop WebGL contexts near 16.
Sit well under the cliff." Everything else is a card. Pins are promoted first and
counted *inside* the budget (`lod.ts:28`), capped at `PIN_MAX = LIVE_BUDGET - 1`
(`:135`) so the focused panel always has a slot, with a named refusal at `:150`.
`Canvas.tsx:2261-2276` enforces the invariant and evicts oldest-held-first.
Hysteresis and a 240px cull margin (`lod.ts:22`) stop edge thrash.

This is well-engineered and honestly described (`README.md:23-26,593,754`). It is
also *lower than the marketing implies*: "an infinite canvas of real terminals"
sets an expectation that "four hundred panels spend the same eight slots"
technically satisfies and emotionally does not. Panels 9+ are cards — their
processes run, but you are not watching them.

**Machine cost is measured, not guessed.** `src/main/machine-cost.ts:96` takes
**one** `ps -axo pid=,ppid=,%cpu=,rss=` snapshot per tick for the whole canvas,
aggregates recursively over the process tree (a panel's pid is a shell or tmux
client; the agent burning CPU is a descendant, so a non-recursive sum would
report ~0% beside a spinning fan), and totals the union of pids so nested targets
cannot double-count. A `ps` failure yields an empty snapshot and the renderer
**keeps its previous reading** rather than rendering a confident `0.0%`. The
renderer owns the poll timer so a closed canvas stops the work immediately.

**What is not stated anywhere a user will look:** how much RAM eight live
terminals plus N agent processes actually cost, or what the practical panel count
is before layout/render degrades. There is no published benchmark.

**Who it eliminates.** Few — but it sets up disappointment at exactly the moment
a user is trying to justify the tool. **Cost to fix.** Low: one honest paragraph
in the README ("eight live terminals at a time; the rest keep running as cards")
plus a measured RAM figure. **Verdict: friction.**

## 14. Support surface: excellent for a maintainer, nearly absent for a user

**Present and good:** MIT `LICENSE`; `SECURITY.md`; `CONTRIBUTING.md` (61 lines,
with the two conventions that actually matter — a check's comment explains the
failure it guards, and watch a new check fail before making it pass); a bug
template that asks the right questions (`.github/ISSUE_TEMPLATE/bug_report.md`
asks for macOS version, Apple Silicon vs Intel, dmg vs source, `tmux --version`,
and the session backend named in the HUD); a feature template; a PR template; a
CI badge.

**Absent:** every one of the 9,774 lines in `docs/` is maintainer-facing —
`load-bearing.md` (3,974), `load-bearing-recovered.md` (2,813),
`ideas-backlog.md` (2,311), `verify-suites.md`, `dead-end-audit.md`,
`build-log/` (one file per milestone). There is **no user guide, no tutorial, no
FAQ, no troubleshooting page, no website, no demo video**. The README is the
entire user documentation, and it is structured as an engineering document: 981
lines, of which the milestone table alone runs ~140 rows, and "Install" does not
appear until line 195 — *after* "What it does not do."

Two more honesty notes worth keeping in view. `docs/load-bearing.md:3860-3973`
maintains an explicit, re-read-every-milestone list of **manual-only
verifications** — facts `npm run verify` cannot prove, including that a real
`claude` responds to `AUTO-DONE`, that a real `git push` from a lane reaches a
remote, that a real PR was never opened, and that `cursor-agent` was never
measured at all (`README.md:909`, declined by name). That discipline is rare and
should be advertised, not hidden. And the bus factor is stated in the security
policy itself: *"This is a beta maintained by one person; expect an
acknowledgement within a week"* (`SECURITY.md:7-8`).

**Cost to fix.** A 150-line `docs/getting-started.md` — install, get past
Gatekeeper, install one CLI, spawn one panel, one screenshot per step — is an
afternoon and would carry more adoption weight than the next milestone.

**Verdict: friction, compounding.**

# The five things

**Only two of these five are code, and that is the finding.**

### 1. Make the repository public and publish a real, notarized `2.3.0` release. *(not code)*
This is the whole ballgame. Today the project has an audience of one, and no
item below matters until it doesn't. Flip visibility, buy the $99 Apple
Developer membership, wire `notarize: true`, build `universal` by passing the
`arch` argument that `builder-config.cjs:27` already accepts, and
`gh release create`. Signing is the only thing on this entire list that costs
money rather than time, and it simultaneously fixes the Gatekeeper "damaged"
dialog (#4), unblocks real auto-update (#5), and rescues the `safeStorage`
caveat the project honestly documents against itself
(`SECURITY.md:80-90`). Add a Homebrew cask the same week —
`brew install --cask terminal-canvas` is how this audience actually installs
things.

### 2. Show the product. *(mostly not code)*
Commit six of the PNGs `npm run shot` already produces and put them at the top
of the README; record a 20-second GIF of the dispatch → worktree → PR loop.
Then restructure the README for a stranger: what it is, a picture, install,
first five minutes — and move the ~140-row milestone table and the architecture
essay to `docs/`. The current README is a superb engineering document and a poor
landing page; those are different artifacts and it is currently only the first.
Add a `docs/getting-started.md`. This is an afternoon of work standing between a
world-class engineering effort and anybody's ability to perceive it.

### 3. Ship an update path, even a dumb one. *(code, small)*
A startup check against the GitHub releases API and a dismissible "3.0 is
available" notice. This works unsigned and ships today; real `electron-updater`
follows once #1 lands. Without it, every install is a fossil — and because this
app parses *other vendors'* CLI stream formats (claude 2.1.259, codex, copilot
1.0.83, ACP), a fossil install does not merely stagnate, it eventually breaks.
This is the difference between "used it once" and "week three."

### 4. Make the defaults safe and the environment honest. *(code, small)*
Ship a non-zero `agents.budgetUsd` and `agents.maxConcurrent`
(`settings-schema.ts:150-169`) — the enforcement is already built and tested,
only the default is wrong, and today the app grants unlimited spend by default
while correctly granting zero filesystem access by default. In the same pass:
add `copilot` to `REPORTED_CLIS` (`env-report.ts:8`), stop rendering a
timed-out shell probe as "not installed" (`presets.ts:224-239` +
`Launcher.tsx:105`), put real install *commands* in the `INSTALL` map
(`Launcher.tsx:50-53`), and close the broker's no-teammate write path
(`broker.ts:229`). Each is small; together they remove the three ways a new
user's first ten minutes can go quietly wrong.

Then spend the remaining half-day on `SECURITY.md`, which is the best asset this
project has for the corporate reviewer and has quietly drifted: correct the
"first and only outbound network call" sentence (`SECURITY.md:53-56`), add a
Privacy/Telemetry section (default off, no vendor DSN, user's own project,
allowlist scrub, minidumps separately opt-in, SDK ships regardless), document the
`terminal-canvas://open` door, lift the places caveat out of `CLAUDE.md:456`
("the gate bounds what the app does for a teammate; the CLI's own tool calls are
the CLI's permission system's"), and link the file from the README.

### 5. Decide, in public, whether this is single-player. *(a decision, then code)*
Right now it is, entirely: everything lives in one machine-local `layout.json`
under `userData`, and templates, lineups, routines and teammates — the artifacts
a team would most obviously want in-repo — cannot be exported, imported, or
committed. If the answer is "teams," then a `.tcworkspace.json` read from a
repository root is the highest-leverage feature on the roadmap and worth more
than another engine. If the answer is "one person at the desk" — which is what
the Launcher's own hero line says (`Launcher.tsx:71`) — then say so on the
landing page and stop paying for the ambiguity. Either answer is fine. The
current state, where the product is single-player but doesn't say so, loses the
team evaluations *and* gets no credit for focus.
