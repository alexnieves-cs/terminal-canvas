# Terminal Canvas 5.0.0

Unsigned macOS build (Apple Silicon). Gatekeeper will object the first time; the README's
Install section and `docs/getting-started.md` both say what it will say and what to do. Nothing
in this release phones home: the update notice (3.0) stays off by default, and the one new
outward door — Prepare feedback… — opens a draft in your browser and submits nothing.

## What is new since 4.1

4.1 made the app read as a product. 5.0 makes it an **authoring surface**: the canvas now holds
objects you make rather than only sessions you start, the workflow is edited where you look at
it, and a canvas can leave this machine as one file.

- **A first conversation, and a canvas to learn from.** The empty canvas has one filled start
  that uses whichever engine is installed. Discovery reports three states per engine — installed,
  missing and *unanswered* — and installed never means signed in; the first message is what finds
  that out. **Open the starter canvas** lays out one captioned example of each kind beside your
  agent and starts none of them.
- **One workflow, two editors.** The workflow panel is an editor: a library you drag from, ports
  you wire (a loop is refused while you drag, and nothing is committed), and the inspector
  editing the selected block's own fields. **Save** writes the draft back and refuses a record
  someone saved underneath you, keeping your work. **Run** runs the shape you can see, and a run
  records the shape it ran — so a later edit never rewrites what a finished run shows.
- **Blocks that do work.** An **Action** block runs one canvas verb line through the same
  executor the palette and `tc plan` use. A **Fetch** block does an HTTP GET; every other method
  is refused by name, because a write belongs on the approval path this app already has.
  **Test this node** runs one block on its own with its duration and a named failure, and starts
  none of its neighbours.
- **A preview that reads as the app beside its code.** Discovery names the project and where its
  answer came from and *executes nothing* — one `lsof` over the panel's own processes and one
  `package.json`; a dev script is offered, never run. Named device widths lay the page out (they
  do not scale it), Capture writes a real picture onto the canvas, and a file change reloads only
  a page served from your own machine.
- **Pictures and notes as equal objects.** Drop or paste a picture and the app keeps a copy of
  its own, named by the picture's content; if the bytes go missing the object stays with a
  **Replace** button. Sticky notes, free text and named regions are one kind with three forms —
  and a region's interior takes no gesture, so clicking inside it reaches what is in there.
- **A canvas that travels.** **Export this canvas…** writes one file that says what travelled,
  how many secrets it scrubbed, and what it left out and why. Pictures' pixels travel only when
  you ask. **Import a canvas…** makes a new workspace, gives everything new identifiers, and
  starts nothing — including the first Run: a workflow that arrived in a file holds verb lines
  somebody else wrote, and it is refused until you have read them.
- **Feedback you can read first.** Help ▸ Prepare feedback… opens an issue draft in your own
  browser with the version, your platform, which engines were found and what is open — scrubbed,
  with the count in the draft. This app does not submit it.

## What did not change

Every 4.1 rule still holds and is still checked: the face rule, the rest rule, the path rule, the
metrics rule and words rather than codes. The webview guest's five hardening rules, the
credential store's three readers, the outward gate and the broker's audit are untouched; the two
`redactSecrets` callers this run added are named in `verify:verbs gate.2` with their reasons.

## What is not here, and why

- **Slack, email, webhook and cron nodes.** Each needs a workspace token, a sender domain, an
  armed listener whose lifetime crosses a relaunch, or real elapsed minutes with a sleep and a
  wake. This run could prove none of them, and a node shipped untested against its own service is
  a promise made on your behalf.
- **A shell node and a transform node.** The terminal node already runs commands with a process
  seam and an approval story; a transform node needs an expression language this run could not
  design and measure honestly, and a half-designed one becomes a compatibility burden the moment
  a saved workflow holds it.
- **An extension registry and an example plugin.** A declarative plugin loader is a new trust
  path into Electron, the filesystem and the credential store, and the standard it was written
  against requires an example installed from an external directory by a person. Neither is here
  rather than a loader nobody has run from outside this repository.
- **A signed build.** Signing needs a paid Apple Developer account, which this project does not
  have. The right-click Open is the step that gets you past Gatekeeper once.
